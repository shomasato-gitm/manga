# FFmpegによるモーションコミック（Phase 4）

**完成・書き出し → 動画制作・MP4出力**から使います。6工程のメニューを維持しています。
画像・WAV・字幕を再利用するローカル処理だけで、有料API・自動TTS・素材の自動ダウンロード・SNS投稿は行いません。
既存の作品500円／全作品月間5,000円の予算管理を変更しません。

## 出力

| 計画・ファイル名 | 寸法 | 形式 | 目標尺 |
| --- | --- | --- | --- |
| youtube_main.mp4 | 1920×1080 | H.264 / AAC、yuv420p、16:9 | 180〜300秒 |
| tiktok_vertical.mp4 | 1080×1920 | H.264 / AAC、yuv420p、9:16 | 45〜75秒 |
| youtube_shorts.mp4 | 1080×1920 | H.264 / AAC、yuv420p、9:16 | 45〜75秒 |

既定24FPS、30FPSと軽量確認用12FPSも選べます。AACは48kHz・ステレオ、faststart対応です。
目標尺は警告の基準で、短い音声を水増ししたり、発話を途中で切って条件に合わせたりしません。実尺を画面と履歴へ表示します。
短い検証用作品は本番尺を満たす作品とは扱いません。

## 必要な素材

1. 保存済みストーリー・人物・コマの採用PNGを用意します。
2. 「音声制作・字幕」で必要な発話のWAVを保存し、字幕・タイムラインを新しい版として保存します。
3. タイムラインの全コマに採用画像が必要です。画像欠損・ハッシュ不一致・古い台本／音声／画像／確認状態は、動画開始時に停止します。
4. モックのトーンや未試聴・未確定脚本は警告を確認したうえで検証用に使えます。日本語の完成音声や公開可能な素材と誤認しないでください。

入力契約は [VOICE_TIMELINE.md](VOICE_TIMELINE.md) の `manga-voice-timeline` schema_version 1です。
JSONの形だけでなく、実ファイルのSHA-256、PNG、16kHz/16bit/mono WAVの実尺・codecを照合します。
既存のストーリー・音声JSON形式は変更しません。画像解析による顔検出は行いません。

## 画面の使い方

1. 作品を開き、動画制作画面で音声タイムラインを選択します。
2. 「編集計画」で3形式を切り替えます。本編は全コマの順序・音声尺・余韻を維持します。
3. 縦型ではコマ全体または1発話を選び、選択順を反映します。「前へ／後へ」で並べ替えられます。1発話を選ぶとWAV全体と対応字幕を使い、文の途中では切りません。
4. モーション（静止・ズームイン／アウト・左右パン）、カット／フェード、画像の収め方、字幕の上下、任意のフック文を編集します。
5. 注目領域を使う場合は「focus」を選び、元画像の左・上・幅・高さを0〜1で指定します。軽量プレビューで確認してください。
6. 必要ならBGM/SFXを明示登録し、音量・開始時刻・フェードを指定します。利用権チェックが必要です。未指定でも声と無音だけで出力できます。
7. 「3形式の編集計画を保存」を押します。未保存の設定では動画を生成しません。キャンセルは最後の保存内容へ戻します。
8. 「生成・進行状況」で出力形式を選び「素材・版・字幕を検査」を押します。ページ・コマ付きの不足情報、正確な尺と警告、保存先を確認します。
9. 確認チェック後に生成を開始します。処理はバックグラウンドで進み、「状態を更新」で形式別の実処理シーン数を表示します。架空の経過率は表示しません。
10. 「出力履歴」で完成ファイルを選び、1本だけ読み込んで再生・ダウンロードします。再出力時も過去ファイルを保持します。

TikTokとShortsは独立した編集計画です。初期案は75秒を超えないコマの選択案で、Shortsは発話の多いコマを冒頭候補にします。
自動で物語の意味・魅力・フックの正しさを判断したものではありません。45〜75秒に適した素材がない場合は警告し、編集計画は未確認のままです。
フック文は利用者が入力する説明で、新しい声を自動生成しません。

## 人物・字幕が切れない配置

既定は画像全体のフィットと背景ぼかしです。前景に8%程度の左右余白と字幕用の領域を設け、最大4%の緩いズーム／パンでも前景を切らない配置にします。
focusモードは、手動で囲んだ重要領域をすべて含む切り取りが可能な場合だけ使用します。不可能なら全体表示へ戻します。
冒頭にフック文がある場合は字幕との両方の領域を確保します。重要領域は顔の自動推定ではないため、必ず人間がプレビューで指定します。

字幕は元のセリフを使い、話者名や読み仮名を勝手に追加しません。既存の日本語フォント検証・禁則処理を再利用し、背景・縁取り付きのPNGとして合成します。
長文は最小文字サイズでも収まらなければ停止し、勝手に省略しません。フォント未対応文字もエラーにします。
画像のフェード中も字幕はWAVの区間中に読めます。0.75秒未満のシーンは、黒い点滅を避けるためカットにします。
軽量プレビューは配置確認用の静止画です。実際のパン・ズーム・場面転換・音声同期は生成MP4で確認してください。

## 音声と字幕の同期

音声は元WAVのサンプルをそのまま、整数ms×16サンプルの位置へ配置します。無音区間もPCMの無音を入れ、映像と音声トラックを継続します。
縦型の並べ替えも発話・字幕を同じオフセットで移動します。
映像のシーン境界は累計時刻をFPSへ切り上げて決め、コマごとの丸め誤差が積み上がらないようにします。字幕の表示差は最大1フレーム程度です。
許容値は±250ms。短尺fixtureのMP4から音声と字幕画像を実際にデコードして測定します。

BGM/SFXはWAV/MP3、20MiB、10分、48kHz以下、1/2chの音声のみです。入力形式を固定して検査し、ネットワーク参照を許可しません。
自動ループ・自動延長はせず、元素材と出力区間の短い方に合わせ、音量・前後のフェードを適用します。リミッターで過大な合成音量を抑えます。

## 保存形式と復旧

| 保存先（作品フォルダ相対） | 内容 |
| --- | --- |
| video.json | schema_version 1 / manga-video-project。revision、計画、計画履歴、任意音声、ジョブ、完成記録、イベント |
| video/audio/UUID.wav・.mp3 | 明示登録したBGM/SFX。利用権確認とハッシュを保持 |
| video/jobs/UUID/ | 元素材の検証済みコピー、一時クリップ、合成WAV、処理ログ、実コマンド、保存再開記録 |
| video/cache/SHA.mp4・.json | 素材・字幕・設定・フォント・レンダラー版に基づくクリップキャッシュ |
| video/exports/JOB_ID/*.mp4 | ffprobe検証後、ハードリンクで原子的に確定した完成ファイル |

各計画は `format: manga-video-plan`、`schema_version: 1`、`timeline_id`、`kind`、`rows`、FPS・字幕・権利確認・BGM/SFX等を持ちます。
各行は `scene_id`、任意の `utterance_id`、motion、framing、focus、gap_after_ms、transition。人物ID・WAV・画像は元タイムラインへ参照します。
完成履歴には元タイムライン版、入力fingerprint、MP4ハッシュ、実測寸法・codec・FPS・尺・音声形式・生成日時・警告を記録します。
`publication_review_required` は常にtrueで、生成成功は公開の自動承認ではありません。

同じ素材・設定の出力は完成済みファイルを再利用できます。明示的な再出力は新しい履歴を作り、検証済みクリップを再利用します。どちらもAPI費用0円です。
作品ごとのロックで重複ジョブを拒否し、実行中は編集計画の保存を止めます。複数アプリの同じ作品もファイルロックで保護します。
別作品を並行実行する場合はMacのCPU・メモリに注意し、必要なら1件ずつ処理してください。

処理は `queued / running / ready / failed / cancelled / interrupted` で管理します。失敗した一時MP4は完成履歴に並べません。
中断ボタンは実行中のFFmpegプロセス群を終了します。クリップ180秒・最終合成300秒・ジョブ全体1時間の上限があります。
1ファイル512MiB、計画10分まで、PNGは1200万画素・25MiB、WAVは25MiBまでに制限します。
空き容量は開始前に素材分＋映像／キャッシュ予算＋128MiBを確認します。保存中に容量が不足した場合も元データは変更しません。

アプリの強制終了・停電ではrunningが残る場合があります。「出力履歴 → 保存再開／中断状態を確認」で、完全な保存記録があれば再検証して保存だけ再開します。
記録が未完成ならinterruptedへ移し、無料で再出力します。別プロセスが実行中なら状態の書き換えを拒否します。
完成品のリンク後にvideo.json保存が失敗した場合も、同じジョブで重複記録・上書きなしに再開します。
実行中に元台本・画像・音声が変わった場合は、古い結果を完成扱いにせず停止します。

履歴・キャッシュ・一時素材は自動削除しません。作品フォルダ全体と、別保存の予算DB／初期化記録を停止後にバックアップしてください。
動画バイナリをソースGitや既存GitHub作品同期へ自動追加しません。大きなファイルはローカル容量に計上されます。

## Macで更新・確認する

マージ後、アプリ停止とデータのバックアップを行ってから更新します。

```bash
cd /実際の保存場所/manga
git switch main
git pull --ff-only
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
ffmpeg -version
ffprobe -version
ffmpeg -hide_banner -encoders
python -m streamlit run app.py --server.address 127.0.0.1
```

Python 3.11・Streamlit 1.40.2を維持し、追加pip依存はありません。FFmpeg/ffprobeはOSコマンドです。libx264とAACエンコーダーが必要です。
FFmpegはlibx264対応の比較的新しい版（5.1以降を想定）を使用してください。検証環境の実測版は検証記録に記載します。
macOS 12・Intelでは、利用中のパッケージ管理ツールがOSに対応していることを確認してください。
対応済みHomebrew環境なら `brew install ffmpeg`、MacPorts環境なら `sudo port install ffmpeg` が導入例です。未対応OSへ新しいHomebrewを無理に導入しません。
既存の互換ビルドを使う場合もPATHから両コマンドを認識できる状態にします。不在なら動画画面だけ停止し、漫画・音声画面は利用できます。

`MANGA_DATA_DIR`、`MANGA_BUDGET_DB` は更新前と同じ外部保存先を指定します。ZIP更新では旧フォルダを残してください。
まずモック素材で生成し、QuickTime Player等とアプリの両方で、人物・字幕・音声・実尺・再出力を確認します。Mac実機での性能・動作は未検証です。

```bash
# 必ず、まだ存在しない出力先を指定する。既存作品は使わない。
python scripts/verify_video.py --output /tmp/manga-video-new-demo
python -m pytest -q
```

検証スクリプトは8ページ24コマの図形PNGと確認用トーンを新規作成・採用し、数秒の3形式MP4とreport.jsonを保存します。
実際のユーザー画像や日本語の人声を使った品質検証ではありません。同期測定は10秒以内の専用トーンfixtureだけで行います。
実コマンド例・測定値・件数・制約は [検証記録](../verification/video_phase4.md) を参照してください。

## 次の漫画自動生成Phaseとの接続

新たな漫画生成側は既存StoryStoreとArtworkStoreへ、検証・明示採用済みのストーリー／人物／コマ画像を保存します。
音声工程がvoice-timeline schema 1を保存した後、この動画工程へ渡します。動画生成からAI APIを逆呼び出ししません。
画像やセリフを改善したら、元の版を保持したまま必要な音声・タイムラインを更新し、動画を新しい履歴として出力します。

# ストーリー制作スタジオ

「企画・ストーリー → ストーリー制作スタジオ」で、概要3案から脚本確定まで進めます。
従来の詳細編集・参考作品・履歴・生成JSON取り込み・評価画面も引き続き利用できます。
「ストーリー概要案作成」はスタジオの概要比較工程へ直接入る入口です。ホームにもスタジオを開くボタンがあります。

ChatGPTへの依頼・送信・反復は利用者が行います。OpenAI API・非公式API・ブラウザ自動操作はありません。
依頼の作成だけでChatGPTに送信されたり、ストーリーが確定したりすることはありません。

## 1. 参考作品と技法を選ぶ（任意）

1. 「参考作品・技法」で「登録・編集」から作品を登録します。
2. 「分析」へ切り替え、既存の分析プロンプトをChatGPTへ手動で渡し、分析JSONを保存します。
3. 「使用技法の選択」で最大3作品を選び、各作品から使う抽象的な技法を選択し、保存します。

現行分析のうち「ユーザー要約に基づく」技法だけを分析由来の選択肢に含めます。
登録した技法メモは「登録メモ・未確認」と明記します。「未確認」「不明」の分析を確認済みの事実に変換しません。
未分析・更新前の分析には警告を表示します。未検証のURLを取得したり、作品をスクレイピングしたりしません。

選択技法は、作品ID・登録版・分析ID・根拠・確認状態とともに依頼へ保存します。
作品の固有の人物・場面・展開・セリフを再現せず、独立した創作にするよう全依頼に指示します。
参考作品なしでも制作できます。

## 2. 概要3案を比較・採用する

1. 「概要3案・選択」で「概要3案の依頼を作成」を押します。
2. 上部からプロンプトをコピー／ダウンロードし、ChatGPTへ手動で渡します。
3. 返答をJSONファイルとして保存し、同じ画面で取り込みます。初期値はJSONファイルで、貼り付けへ切り替えも可能です。
4. タイトル・ログライン・あらすじ・葛藤・転換点・結末を3つのカードで比較します。人物・応用技法・独自性・懸念点は詳細にあります。
5. 「この概要案を採用」を押した1案だけを採用します。脚本自体はまだ変更しません。

1依頼の候補数はちょうど3案です。候補ID・依頼IDを照合し、葛藤・転換点・結末が同一の文字列である案は拒否します。
意味上の差別化や独自性を自動保証するものではありません。カードを読み、人間が判断してください。
選択した全技法について各案が応用方法を返すため、どの作品・技法をどの案へ使うか確認できます。

別の3案が欲しい場合は、依頼作成を再度押します。古い3案・不採用案・採用履歴は残ります。
参考作品や分析を更新した後は、古い概要を黙って転用せず、現行分析で概要を作り直して選択します。

## 3. 詳細脚本を生成する

「詳細脚本」で採用概要を確認し、「採用概要から詳細脚本の依頼を作成」を押します。
選択した概要・技法・既存人物設定を自動挿入します。ページ数は作品設定に合わせ、現行脚本が同じページ数なら各ページのコマ数も引き継ぎます。脚本がなければ各ページ3コマが初期値です。

回答の外側には次の識別情報を付けます。**内側のstoryは従来のschema_version: 1の脚本JSONそのものです。**

```json
{
  "schema_version": 1,
  "request_id": "依頼プロンプトにあるUUID",
  "project_id": "対象の作品UUID",
  "story": { "schema_version": 1, "title": "採用概要のタイトル", "summary": "あらすじ", "pages": [] }
}
```

この例のpagesは説明用です。実際には専用プロンプトの全ページ・全コマを埋めて返してください。
外側のIDをstory内に追加しません。従来画面で扱う脚本本体の形式は変更していません。
依頼・作品・版・設定・採用概要を検証し、保存時は新しい脚本版を追加します。既存の脚本本文・履歴は残ります。
概要候補ID、採用ID、依頼ID、参考作品の版と分析IDを追跡できます。

## 4. 評価 → 改善 → 再評価

「評価・改善」では現在版と、**その版に対する最新評価**だけを初期対象にします。

- 未評価：評価依頼を作成 → プロンプトをコピー → 評価JSONを同じ画面で保存。
- 評価済み：改善依頼を作成 → プロンプトをコピー → 改善JSONを保存。
- 改善版保存後：新しい版を評価。過去版の点数を新しい版の評価として使いません。

改善の詳細設定は折りたたんであります。初期値は最新評価の問題点・理由・改善案・対象コマから作成します。
全体改善、ページ・コマ限定、評価項目重点の3方式を選べます。部分改善の範囲外に変更があれば保存を拒否します。
設定を変えたら新しい改善依頼を作ります。作成済みの依頼やプロンプトは上書きしません。
最新評価が更新された後の古い改善依頼、別の版の評価、依頼後に設定が変わった回答は拒否します。

評価は8項目各10点で、従来処理が合計÷80×100を計算します。
参考技法の活用状況、オリジナリティ、矛盾の指摘も回答に含めます。改善版の評価依頼には改善前の脚本・評価・実際のJSON差分を添付します。
点数の低下はアプリが数値で検出します。意味上の矛盾はAIの未確認提案であり、アプリが画像や文章を自動理解して保証するものではありません。

**AIの評価点は主観的な参考値です。品質の客観的な保証ではありません。**
このPDCAは脚本の制作を管理します。完成画像の品質チェック・GitHub同期側の品質PDCAは従来の完成工程から利用できます。

## 5. PDCAの目安と最終確定

- 目標点：初期値85／100。
- 改善回数の目安：初期値3回。設定変更可能です。
- 回数は現在版の系譜で計算します。別の概要から新しい詳細脚本を作ると、その脚本から数えます。
- 目安到達後は「追加改善を行う」を選び、理由と回数を保存しない限り改善依頼を作成しません。
- 「追加せず比較・最終確認へ進む」も選べます。評価・再評価は目安到達後も可能です。

「比較・確定」では各版の総合点グラフ、8項目の点数変化、項目別得点差、問題点、改善理由、実際の描写・セリフ等の変更を確認できます。
未評価の版は未評価のまま表示し、推定点や過去点で埋めません。

目標達成だけで自動確定しません。人間がテーマ・世界観・人物・独自性・変更箇所を最終確認します。
目標未達、点数低下、未確認の技法活用、古い分析や矛盾の指摘がある場合は、残る課題の明示承認も必要です。
表示後に別画面で脚本や評価が変わった場合、そのまま確定せず更新を求めます。
確定後はキャラクター・作画工程へ進めます。確定後の修正は既存の作画指示・画像との整合を再確認してください。

過去版は比較画面か従来の履歴画面から復元できます。復元は新しい版として追加し、元の版を残します。復元後も新しい版として再評価します。
スタジオ生成後の手動ページ編集では生成元を引き継ぎます。無関係な通常の新規JSON取り込みに古い概要を推測で割り当てません。

## GitHubによる受け渡し

「完成・書き出し → GitHub作品同期」を使います。

1. スタジオで依頼を作成し、その作品だけのスナップショットをGitHub作品ブランチへ保存します。概要段階だけでも保存可能です。
2. 実際に利用できるChatGPT／Codex等のGitHub連携で、依頼を読み、回答を `works/<作品ID>/responses/<任意の一意名>.json` にコミットします。書き込み機能がない場合は利用者がGitHubへファイルをアップロードします。
3. アプリの「AI提案・画像レビューの回答」で「ストーリー制作スタジオの回答候補」を選びます。
4. 取得・検証して候補へ保存し、確認後に受信箱へ登録します。この時点でも脚本・評価・概要採用は変わりません。
5. スタジオへ戻り、該当依頼の受信したJSONを確認して保存します。概要ならさらにカードから1案を採用します。

スナップショットからの復元では「概要案・選択・制作PDCA」を明示選択します。対応する脚本が必要な場合はストーリーも同時に選びます。
脚本作成前の人物設定・基準画像も同期できます。その場合は人物・画像の範囲も明示選択します。脚本のないコマ画像・作画指示は概要のみの同期へ混ぜません。
参考分析・評価を履歴に追加し、同じIDで異なる記録や設定があれば上書きせず停止します。
別端末の脚本確定は履歴として残し、この端末で最終確認した扱いにはしません。
候補取得だけで正式作品を更新しません。旧ストーリー・画像・人物ID・候補・評価・ページ編集の削除は行いません。

概要だけのスナップショットは外側のmanifestに `content_kind: "concepts"` と `story_version_id: null` を持ちます。
従来の脚本スナップショットとstory本体はそのまま読めます。新機能の同期先もこの版へ更新してください。旧アプリは新しい同期種別を検証できず停止する場合があります。

## 保存・中断・容量

`<MANGA_DATA_DIR>/<作品ID>/story_concepts.json` に概要・依頼・技法・採用・生成元・PDCA設定・受信箱・制作履歴を保存します。
脚本は既存の `story_history.json`、分析・採点は既存の `editorial.json` です。story_historyの新しい版だけに親版IDを追加します。旧履歴を移行・削除する必要はありません。
人物・参照画像・画像候補・composition.json等を制作スタジオが自動変更することはありません。

複数ファイル保存は、既存のファイルロックと変更前後の保全・再開記録を利用します。
中断時は他画面で編集せず、「制作保存を再開」を押します。別編集があれば自動上書きせず停止します。先に保存フォルダ全体をバックアップしてください。
ディスクの電源断まで含む単一データベースのトランザクションではありません。ローカルのロック・ハードリンクに対応する保存先を利用します。

制作履歴は8MiBまで、既存同期は1ファイル10MiB・1回100MiB等の上限を維持します。上限時に履歴を自動削除しません。
更新前はアプリを終了し、`MANGA_DATA_DIR` 全体をコピーしてバックアップします。ZIP更新でも外部保存先を指定すればコードとデータを分離できます。

## APIなしの動作確認

各依頼の「APIなしの動作確認サンプル」から、その依頼IDに対応する架空JSONをダウンロードできます。
概要3案 → 採用 → 詳細 → 評価 → 改善 → 再評価をサンプルで試せます。本番作品への採用は人間が判断してください。
生成コードは `manga/story_studio_samples.py` にあり、pytestとStreamlit AppTestも同じ回答契約で検証します。

```bash
python -m pytest -q
python -m pytest -q tests/test_story_studio.py tests/test_story_studio_app.py tests/test_story_studio_sync.py
```

Python 3.11・Streamlit 1.40.2・既存依存パッケージを使います。実行用パッケージやAPIキーの追加はありません。

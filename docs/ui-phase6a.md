PR #13がマージ済みであることをGitHub APIで確認し、最新main `f2a97ec914aaa3b9e55640ec4361e33f2fe3ef15` から `feature/phase6a-studio-ux` を作成した。

## 日常の操作

サイドバーの7つの主要メニュー（ホーム／企画・脚本／キャラクター／画像制作／漫画編集／音声・動画／設定・管理）で移動する。現在の作品・主要工程・作業は本文上部のパンくずに表示する。工程内のよく使う作業は本文のボタンで直接開ける。前後の工程へ移動するボタンも用意した。

旧6工程と全作業セレクターはサイドバーの折りたたみに残している。既存の内部ルート、保存済みリンク、各画面の編集・採用・診断・復旧・履歴機能にアクセスできる。表示モードは標準を既定とし、詳細モードでは内部情報を開いて確認できる。モード切替で入力キーを変えない。

| 画面 | 改善前 | 改善後 |
|---|---|---|
| ホーム | 長い工程表・説明が中心 | 上部に次の作業と再開、全体進捗、未完成コマ、工程カード、詳細条件。最近の成果物は既存Storeから表示 |
| 企画 | 最大5列の長文 | 2列カードに要点を表示。全文は詳細へ。選択中の企画は別領域に表示し、正式採用との違いを明記 |
| 脚本比較 | JSONの差分が中心 | 変更された項目を変更前・変更後の2列で表示。元のJSON差分・評価・採用確認も維持 |
| 人物 | 先に人物セレクターから探す | 基準画像・名前・役割・主な特徴・入力状況のカード。編集／基準画像／バイブルを人物ごとに直接開く |
| 画像 | ページ・コマの多段選択 | ページ絞り込み・未完成フィルター付きの全コマグリッド。対象カードから手動制作画面へ直接移動 |
| 手動画像 | 描写を別画面で参照、内部IDが目立つ | 描写とセリフを同じ画面に表示。プロンプト・参照取得・アップロード・比較・確認・採用・次コマを既存処理で連携。UUID/SHA/確認票JSONは詳細へ |
| 漫画編集 | ページセレクターから選択 | ページ番号ボタンも追加。既存の大きなプレビュー、編集対象選択、未保存表示、保存・取消・履歴を維持 |
| 音声・動画 | 作業ラジオだけで切替 | 順序と現在位置を示す手順ボタンを追加し、既存の設定・生成・試聴・字幕／動画編集・検査・MP4・再生へ接続 |
| 設定 | 完成工程の中から探す | 作品管理・保存先診断・予算・GitHub同期の入口をまとめる。実行は各画面での確認後のみ |

人物の「入力状況」は入力欄の充足数であり、外見や権利の承認ではない。ホームの完了判定は既存dashboardを使用し、モックや未確認素材を承認済みにしない。代表画像は明示表示で先頭の採用画像を取得し、自動で表紙に採用・保存しない。最後に開いた画面は作品ごとにセッション内で保持し、最近保存した成果物は再起動後も既存Storeから取得する。

## 操作回数の比較

以下はホームから目的の作業へ進む際の「選択・ボタン操作」を数えた比較。ドロップダウンを開くクリックやスクロールは含めない。既に対象が選択済みの場合は旧UIでも少なくなる。

| 作業 | 旧UIの代表的な経路 | 新UI |
|---|---|---|
| 主要画面へ移動 | 工程→作業の2選択 | 主要メニュー1回 |
| 指定人物のバイブル | 工程→作業→制作段階→人物の4選択 | キャラクター→人物カードのバイブル、2回 |
| 別ページの指定コマを制作 | 工程→作業→ページ→コマ、4選択 | 画像制作→対象カード、2回（表示中の12コマ内） |
| 漫画編集 | 1回 | 1回を維持。各ページへの番号ボタンを追加 |

音声・動画は説明と順序を優先し、全操作が一律に減ったとはしていない。全24コマのグリッドは最大12件ずつ表示するため、次の一覧ページへの移動が必要な場合がある。

## 共通部品と安全性

`manga/ux.py` にヘッダー、ステータス、進捗カード、サムネイル、空状態、詳細、手順・ナビゲーションを集約した。`ux_screens.py` は一覧とガイドを担当し、保存・採用は既存画面へ委譲する。共通UIラッパーは標準モードで技術的なcaptionとJSONを折りたたむが、エラー・警告は折りたたまない。ボタンの説明は有効・無効によって識別が変わらないようにした。

Streamlitの公開コンポーネントとlightテーマを使用し、アクセントをインディゴに統一。CSSは静的な見出しサイズの調整だけで、Streamlit内部DOMセレクターに依存しない。大きなサムネイルや長い本文を常時並べず、表示中のカードだけを読み込む。

データスキーマ、作品UUID、画像ID、予算500円／月間5,000円、有料画像送信無効、下書きキー・保存復旧・差分更新・GitHub同期契約は変更しない。採用・権利確認、課金・外部送信・SNS投稿を自動化しない。

## Macでの確認

```bash
git fetch origin
git switch feature/phase6a-studio-ux
python3.11 -m venv work/mac-ui-venv
source work/mac-ui-venv/bin/activate
python -m pip install -r requirements-dev.txt
brew install ffmpeg
python -m pytest -q
python scripts/verify_production.py --output work/mac-ui-demo
MANGA_DATA_DIR="$PWD/work/mac-ui-demo/data/projects" python -m streamlit run app.py
```

既存の作品領域を使わず、新しい検証作品で確認する。標準／詳細切替、7メニュー、人物とコマの直接移動、企画選択と正式採用の区別、未保存入力の保持、保存結果、音声・動画の各手順、旧6工程へのアクセスを確認する。1440px／1280px／狭い画面では、サイドバーを開閉し、カード・主要ボタン・プレビューが操作できることを確認する。Python 3.12では別venvで同じ全pytestを実行する。

## 残る改善余地

今回は既存Streamlitの機能と入力キーを維持した段階的な整理。診断・高度な編集には従来のラジオやセレクターも残る。真の表紙指定、最後の作業位置の端末間永続化、書籍全ページのサムネイルキャッシュ、全画面の長文をさらに整理する作業、音声生成と試聴の独立画面化、スクリーンリーダー/キーボード利用の実ユーザー検証は今後の候補。Mac実機と実作品の外見・音声・権利の確認は別途必要。

# AI画像生成・採用（Phase 2-D1）

「イラスト制作 → AI画像生成・採用」を追加しました。既存6工程、基準画像登録、コマ制作ワークスペース、音声・動画は残しています。
**今回使えるのは無料モックと手動取り込みです。有料画像APIのアダプターは未実装・送信不可です。** キーや有効化フラグを設定しても送信しません。

## 1. 元の脚本と人物を準備する

1. 最新の正式脚本を「企画・ストーリー → 比較・脚本確定」で人間が確認・確定します。AI候補UUIDは使いません。
2. 人物を正式採用し、「キャラクター・作風 → AIキャラクター制作・一貫性管理」で固定特徴・別名・場面例外とバイブルを確認します。
3. 各コマの最新の作画指示に人物UUID、場所・時刻・構図等を保存します。服装変更は対象コマ付きの例外にします。

コマ画像では登場人物全員の基準画像が必要です。未登録なら先に基準画像の候補を作ります。
同名・曖昧な話者、固定設定の矛盾、古い脚本・バイブル、参照の欠損・SHA不一致は理由を表示して停止します。人物の名前をUUIDの代用にはしません。

## 2. 生成計画

「全コマの制作計画を確認・更新」で8ページ24コマ等の状態を確認します。未準備・候補あり・採用済み・要再確認を表示します。
一覧は更新ボタンを押した時点の記録です。保存・採用・参照変更後は再更新してください。非表示画面で計画や画像を全件読み込みません。

対象は「人物の基準画像」または「漫画のコマ画像」から一つ選びます。
基準画像は人物UUIDと正面／斜め／全身／表情差分、コマ画像はページ・コマ番号を指定します。
1024×1024、1536×1024、1024×1536からサイズを選び、必要なら構図補足、重要領域の中心・幅・高さ、字幕や見切れ防止の余白を設定します。
座標は0〜1の比率で、画像外へ出る領域は拒否します。これは演出計画の記録で、画像認識による顔の検出ではありません。

「この対象の生成計画を作成」で、固定特徴・衣装例外・作風・カラー設定・参照ID／SHA・想定レイアウトを組み立てます。
セリフ・吹き出し・字幕・文字・透かしを描かない既存規則を含みます。
プロンプトのコピーとダウンロードを全文より先に表示し、参照画像は任意に選択した1枚だけ確認・取得できます。
**アプリは参照画像を外部送信していません。ChatGPT等で生成する場合、利用者が実際に画像を添付してください。**

## 3. 無料モック／手動取り込み

「生成・手動取り込み」で保存した計画を確認し、方法を選びます。

- 無料モック：Pillowの図形と`TEST IMAGE - NOT AI`等の表示を持つテスト画像です。AI生成・人物の再現・本番品質を示しません。
- 手動取り込み：ChatGPT等で利用者自身が生成・保存したPNG／JPEG／WebP、または権利のある素材を選択します。外部画面の自動操作はしません。
- 有料API：未対応です。依頼保存ボタンを無効にし、バックエンドも未予約・未送信で拒否します。

手動画像は20MB・2400万画素まで。拡張子と実際の形式、不正画像・画像爆弾・アニメーション等を検査し、既存prepare_imageでPNGにします。
元ファイルのバイト列もimage_ai/jobs内に保持します。EXIF等のメタデータを除いたPNGと区別し、元ファイルを変更しません。画像の透かしを消す処理はありません。
手動画像の実寸が計画と異なる場合は警告し、自動トリミングしません。動画素材には既存の1200万画素上限があるため、高解像度の持ち込みは後工程でも確認します。

「候補作成の依頼を保存」→保存した依頼を選択→「選択した依頼から1候補を作成」の順です。
依頼を保存しただけでは画像を作成・採用しません。1依頼は1候補です。全24コマの有料一括送信はありません。
同じ条件・同じ入力は保存済みの依頼を再利用します。別の候補が必要なら「新しい候補の依頼」を明示選択します。
停止した依頼・生成途中に停止要求があった依頼でも、元画像と保存済み候補は消しません。

## 4. 比較・目視確認・明示採用

「候補比較・採用」で対象を選び、1ページ2候補までの縮小表示から比較します。
選択した1枚だけを拡大・PNG取得でき、手動画像では変換前ファイルも取得できます。モック・手動を区別し、元プロンプト・モデル・参照SHA等は折りたたみます。

顔・固定特徴、衣装、人体、構図、不要な文字、素材権利を人間が確認し、メモ・出典を入力して「目視・権利確認を保存」します。
これは人間による確認記録であり、AIが顔一致率や商用利用を認定したものではありません。
次に正規登録・採用の承認をチェックし、「この候補をArtworkへ登録・採用」を押します。この操作時だけ既存ArtworkStoreへ登録・選択します。

基準画像はadd_reference／select_reference、コマ画像はadd_panel_image／select_panel_imageを使います。
旧人物UUID・旧参照画像・旧基準画像ID・候補・選択履歴は保持します。コマの過去候補を再選択するときも、登録済みIDを使い直して二重登録しません。
モックは正規画像のoriginal_nameにもTEST_ONLYを残し、音声タイムライン・動画素材の警告へ引き継ぎます。

基準画像を変更するとバイブルは古い状態になるため、「バイブル確認へ」で新しい参照を人間が確認します。
複数候補を比較するときは、先に必要な候補を作ってから1枚を選ぶと、基準変更による再確認を減らせます。
古い基準で作った未登録候補を新しい設定へ無断で採用しません。必要ならPNGを取得し、最新計画の手動取り込みとして改めて確認します。既に正規登録した基準画像の切り替えは、従来の基準画像画面も利用できます。

## 5. 更新検知・復旧・履歴

脚本・企画設定・作風・人物プロフィール・対象バイブル・参照ファイル・作画指示・ページ配置を結び付け、プロンプトと画像のSHAを保存します。
別コマで画像を採用しただけでは、すべての候補を古くしません。対象の情報が変わった候補は「要再確認」とし、黙って差し替えません。
画像内容の目視一致は静的ハッシュの一致から推定しません。

| 保存先 | 内容 |
| --- | --- |
| image_ai.json | format:manga-image-ai / schema_version:1。計画・依頼・候補・レビュー・採用・イベントの追記履歴 |
| image_ai/initialized.json | 初期化済み記録。主JSON欠損時に0から始めないため保持 |
| image_ai/candidates/UUID.png | 正規Artwork登録前の不変なPNG候補 |
| image_ai/jobs/UUID/input.bin | 手動画像の元バイト列。入力SHA・元名を依頼へ保存 |
| image_ai/jobs/UUID/receipt.json | 候補PNGのSHA・寸法・保存先・送信0件・費用0円 |
| image_ai/pending_adoption.json | 一意な採用ID、登録前のArtwork、保存段階・登録済み画像ID等の再開記録 |

依頼IDと候補IDを先に永続化します。PNG・応答を保存してから候補一覧を更新し、保存失敗時は「履歴・復旧」から同じ依頼IDで保存だけを再開します。
手動入力の保存に失敗した場合は、同じ入力SHAの元ファイルを再選択します。別の画像を同じIDへ上書きしません。
実API再送経路は存在しません。無料fixture／同じ手動画像は保存前なら再構成できます。設定が古くなって再構成できない場合は、新しい計画へ手動取り込みし、旧候補を保持します。

正規採用が途中の場合は他の編集をせず、画面上部の「画像採用の保存を再開」を使います。
一意な採用印で登録済み画像を照合し、同じ画像ID・選択履歴で再開します。
メタデータが保存済みでPNGだけ失われた中断は、ArtworkStoreの専用復旧処理で欠損ファイルだけを同じIDへ戻します。存在する異なる画像は上書きしません。
別編集・改変された再開記録・SHA不一致では停止します。差分とバックアップを確認し、記録を削除して回避しないでください。

JSON履歴は32MiB、採用再開記録は64MiBまでとし、容量・空きディスクを確認します。自動削除・圧縮はしません。
新しいimage_ai領域は既存GitHub作品同期の自動対象へ追加していません。正規Artworkの従来同期は維持し、候補・元入力を含む作品フォルダ全体もバックアップします。

## 6. 費用と未対応範囲

[公式モデル比較](image-ai-provider-comparison.md)を確認してください。モデル名・単価は日付付き研究JSONで管理し、実行用PriceQuoteとは区別しています。
OpenAIの新画像モデルは単価を確認しましたが、今回の編集・参照生成について厳格な最大総請求量を確認できませんでした。
Google Developer APIの資料は通信制限で取得できず、取得できたVertex料金を同じAPIの費用として扱いません。

「モデル・見積」では確認日・参考単価・サイズ・参照数と、上限が不明で送信不可である理由を表示します。
Vertex画像出力部分だけの参考小計は、テキスト・画像入力・reasoning・再生成・他工程を含まないため総額／最大額ではありません。
ChatGPTやGoogle AI Studioの月額・UI試用をAPI無料枠にしません。「500円で作品完成」を保証しません。
共有残額はボタンを押したときだけ同じopen_budgetで読み、作品生涯500円・全作品月間5,000円を表示します。画像用DBや追加の500円枠は作りません。
モック・手動ではAPI呼び出し0、予約0円・費用0円。将来の有料アダプターも確認済み最大額・個別同意・秘密鍵・既定OFF・共通BudgetedExecutorを必要とし、請求不明を自動解放・再送しない設計です。

## 7. Macでの確認

Python 3.11／3.12、Streamlit 1.40.2、Intel Mac/macOS 12を想定し、追加pip依存はありません。実機は未検証です。
アプリ停止と、作品フォルダ・共通予算DBのバックアップ後、app.pyとrequirements.txtがあるリポジトリ直下で実行します。

```bash
git status --short
git fetch origin feature/ai-image-production
git switch -c review-image-ai FETCH_HEAD
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

同名レビュー用ブランチがあれば新規作成せず選択します。未コミット変更を勝手に破棄しません。mainへマージしません。
MANGA_DATA_DIR・MANGA_BUDGET_DBは既存の外部保存先を引き続き使います。ZIP更新では元フォルダとデータを残してください。

実ユーザーデータを使わない専用検証：

音声・動画素材の検査にはffprobeが必要です。`ffprobe -version`で確認し、未導入なら既存の動画工程と同じく`brew install ffmpeg`で導入してください。

```bash
# まだ存在しない出力先だけを受け付けます。
python scripts/verify_image_ai.py --output /tmp/manga-image-ai-new-demo
# 作ったfixtureだけをアプリで見る場合
MANGA_DATA_DIR=/tmp/manga-image-ai-new-demo/data/projects python -m streamlit run app.py
# 開発用の全テスト
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

fixtureは3人物＋ナレーター・8ページ24コマ、基準候補3・コマ候補25・手動候補1、明示的な一部採用→全24コマ採用を確認します。
32字幕・4個の確認用トーン音声を作り、既存voice_contract・video_sourcesの24入力画像検証へ渡します。日本語音声や完成動画品質の実証ではありません。
report.jsonへ前後のSHA・保持対象・送信0回・予約0円・費用0円、timeline.jsonとsample.jsonを出力します。既存の出力先は上書きしません。

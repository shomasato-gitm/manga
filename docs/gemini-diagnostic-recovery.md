# Gemini初回診断の原因調査と未確定請求の照合

この機能は診断の段階記録と、**提供元で確定した請求結果**の手動照合を行う。
診断・請求の照合ボタンはAPIを再送しない。Codex/CIは実Gemini APIを呼び出さない。
実キー認証、Google側の請求、Mac実機の通信は未検証。

## 現在の未確定1件について

報告された最大予約23.8128円は、実請求額ではない。既存台帳にある金額をそのまま維持する。
Google AI Studioの使用量「データなし」は未送信・無課金の証明ではない。
この開発環境には利用者のMacの診断記録・台帳がないため、その1件の実際の原因・請求を確認してはいない。
旧版の記録に段階別ログがない場合、通信開始前/HTTP応答/形式検証/保存のどこで失敗したかを復元しない。
`network_error`等の既存分類は表示するが、正確な失敗箇所や無課金を推測しない。

1. 新しい診断を実行しない。他のアプリプロセスも停止し、作品データと**同じ共有予算台帳**をバックアップする。
   SQLiteはアプリ停止後に、台帳と`.initialized`、存在する`-wal`/`-shm`を同じ状態で保管する。キー/環境ファイルはGitHubへ送らない。
2. 「企画・脚本 → AI企画・ストーリー → 制作条件 → Geminiの接続・無料枠・料金設定」で対象診断を選ぶ。
   照合用リクエストIDと日時、既存分類を確認する。段階ログがない旧記録は「特定できません」と表示する。
3. 「請求未確定の明細・手動照合へ」から「API予算管理」を開く。対象作品UUID、リクエストID、モデル、日時、最大予約額23.8128円を照合する。
   全作品の未確定明細を表示するため、別作品を選ばないように確認する。
4. キーを発行した正しいGoogleプロジェクトを選び、診断日時・モデル・利用履歴と**確定した請求結果**を確認する。
   無料Tierの表示、HTTPエラー、集計にデータがないことだけでは判定しない。反映待ち、1件に対応付けられない集計、請求額不明なら「未確認・反映待ち」のまま保持する。必要ならGoogle側へ確認する。
5. 結果が確定した場合だけ、明細から対象の1件を選ぶ。
   - 「請求額が確定」：その1件の確定円金額と請求日（日本時間）を入力する。最大予約額を実請求額として流用しない。外貨しか確認できない場合、円の確定額・換算根拠が確認できるまで照合しない。
   - 「無課金が確定」：その1件の無課金を提供元で確認できた場合だけ選ぶ。
6. 確定請求結果の確認と、作品・リクエスト・金額・日付の確認をそれぞれチェックし、
   「確認済みの請求結果をこの1件に反映（再送なし）」を押す。選択・金額・日付を変えたら再確認が必要。
7. 更新された残予算と照合履歴を確認する。他の未確定や見積超過があれば新規送信停止は継続する。
8. 「Gemini初回診断の保存・請求照合へ戻る」で診断画面に戻り、同じIDを選び、
   「診断の保存・請求を照合する（再送なし）」を押す。保存済み応答があれば再利用する。
   有効な応答がない場合は通信成功にしない。無料枠・モデル利用権限・料金設定を自動で確認済みにもしない。

確認できないまま台帳を削除、別パスへ変更、予約を0円へ書き換え、SQLで強制解除しない。
予約中(`reserved`)は実行中の可能性があるため、このUIで解除・精算しない。請求不明(`uncertain`)だけが手動照合の対象。
実請求が見積を超えた場合は実額を記録し、既存の見積超過ガードで停止を継続する。上限に収まるよう金額を小さく入力しない。

## 新しい診断で分かる段階

新規診断のみ、既存AIStoryStoreの不変ファイル保存で
`story_ai/diagnostics/<診断ID>.trace/0001.stage`以降へJSONを追記する。トップレベルの作品JSONスキーマは変更しない。
固定の段階・開始/完了/失敗・日時・HTTPステータス・固定エラー分類・診断IDだけを記録する。
キー、キーの一部/ハッシュ、ヘッダー、URL、リクエスト/レスポンス本文、生の例外は記録しない。

|段階|記録が意味すること|
|---|---|
|通信開始前|保存準備と予算実行権の準備。完了は実行権取得後|
|送信処理|HTTP処理へ進んだ。開始だけでは送信完了・Google到達は証明できない|
|HTTP応答受信|ステータスを受け取った。本文の受信・生成成功・無課金は別|
|応答形式検証|JSON・モデル・利用量・固定文応答の検査。HTTP 200でも失敗し得る|
|結果ファイル保存|既存の不変応答ファイルを保存|
|予算精算|usageの保守換算と共通台帳の精算|
|履歴保存|診断の最終状態を既存AIStoryStoreイベントへ保存|

「未記録」は未実行の証明ではない。ログ保存に失敗したらそれ以降を推測せず停止する。
ログは保存障害で末尾が欠ける可能性がある。応答があっても課金予約は請求照合まで維持する。
再開ボタンは元の通信段階を補完しない。旧記録へ新しい段階を遡って付与しない。

|分類|確認先|
|---|---|
|401|Macのキー設定と発行プロジェクト|
|403|キー制限、モデル権限、地域・組織ポリシー等。原因を一つに断定しない|
|404|モデルID、提供状況、当該アカウントから見えるモデル|
|429|利用回数・トークン・無料枠・一時容量の制限。自動有料切替/再送なし|
|5xx|Google側の障害と利用履歴・請求|
|接続・HTTP応答待ちタイムアウト|urllibの記録だけでは接続確立前か最初の応答待ちか特定できない|
|本文受信タイムアウト|HTTP応答後に本文受信が中断。生成結果・請求は不明|
|レスポンス形式不一致|JSON、モデル、利用量、固定文応答の形式。本文は保存・表示しない|
|保存・精算失敗|保存先容量・権限、既存応答、共有台帳、確定請求|

## Macでの確認

通常の仮想環境で依存関係を更新し、PRのブランチで起動する。

```sh
git fetch origin
git switch feature/gemini-diagnostic-recovery
python -m pip install -r requirements-dev.txt
python -m streamlit run app.py
```

既存の`MANGA_DATA_DIR`と`MANGA_BUDGET_DB`は変更しない。キーは既存の安全な環境設定を使い、コマンド・スクリーンショットへ値を含めない。
この確認のためにAPIフラグを有効化したり、再診断したりする必要はない。
まず旧診断の「段階別ログがない」案内、明細ID/予約額、既定の「未確認・反映待ち」、未承認の反映ボタン無効を確認する。
Google側で確定確認できた場合だけ上の手順を進める。表示確認や画面遷移だけでは予約・正式脚本・人物・音声・画像を変更しない。

オフライン回帰テスト：

```sh
python -m pytest -q
```

フェイクHTTPによる分類、秘密情報非保存、旧台帳の追加更新、全作品予算、個別承認、競合、保存失敗のロールバック、Streamlit操作を検証する。
実際のGoogle障害原因、無料枠、請求、Macのネットワークの成功を保証するテストではない。

## 保存・互換性

共有予算DBへ照合履歴とその版のテーブルだけを追加する。既存の予約・精算・実行権・見積・予算ポリシーを削除/初期化しない。
手動照合は精算と履歴を同じSQLiteトランザクションで保存し、重複操作は拒否する。履歴保存失敗なら予約額と停止状態を保持する。
元の見積と実行権は残り、同じリクエストIDを再送できない。
診断の無料/有料モード、脚本生成、音声、画像API停止、対象確認票、PNG/PDF/MP4、自動進行、同期は変更しない。
作品500円/全作品月間5,000円を維持し、請求不明時の自動解除・自動再送は追加しない。

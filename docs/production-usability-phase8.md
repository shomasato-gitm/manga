# Phase 8：手動画像制作を1画面で進める

画像APIを使わず、正式脚本の1コマから作画指示、外部での画像制作、取り込み、人間の確認、正式採用まで進めます。保存先・作品ID・人物UUID・脚本版・予算・同期の仕様は変更しません。

## 操作フローの変更

| 改善前 | 改善後 |
| --- | --- |
| プロンプト準備を押してから「最新の作画指示を先に保存」エラー | STEP 2に不足理由と作画指示の入力欄を表示。保存前は準備ボタンを無効化 |
| 別のコマ制作ワークスペースへ移動し、対象を確認して保存 | 同じ対象・同じ画面で確認・保存し、STEP 3の条件を再検査 |
| プロンプト・画像・確認票の順番を自分で判断 | 上部の7ステップと次の操作を確認。確認票を画像と保管して取り込み |
| コマごとに人物候補等を入力 | 無料・オフラインで24コマの下書きを比較し、選んだ未保存コマだけ明示保存 |
| 採用後の現在位置が分かりづらい | 現在のコマを保持し、「次の未完成コマへ進む」で明示移動 |

通常の制作では別画面への往復が不要になります。既存の詳細ワークスペースも折りたたみから引き続き開けます。一括準備は「人物一致・外見の承認」ではなく、脚本上の人物候補と明記情報の入力補助です。

## 7ステップ

1. コマの描写・セリフ・ナレーションと、最新脚本の確定状態を確認。
2. 作画指示を確認・修正して「このコマの作画指示を保存」。空欄の演出情報を推測で埋めません。人物候補も人間が確認してください。
3. 「この対象のプロンプトと基準画像を準備」。プロンプト、必要な人物の基準画像、対象確認票を取得。
4. ChatGPT等へ自分でプロンプトと基準画像を渡して画像を作成。画像と対応する確認票を一緒に保管。
5. 画像と制作時の確認票を選び「検証して画像候補を取り込む」。形式・SHA・ページ・コマ・人物UUID・脚本版・プロンプトを既存の検査で照合。
6. 候補を比較し、確認チェックと出典メモを入力して「目視・権利確認を保存」。この操作では採用されません。
7. 別途、採用承認をチェックして「Artworkへ登録・採用」。成功後に「次の未完成コマへ進む」。

上部の「完了」は保存・検証の状態を表します。ユーザーの読了やダウンロード履歴、ChatGPTでの操作を監視しません。外部制作の証拠は保存済みの手動画像です。モックだけから実画像制作完了とは判断しません。作品全体の公開品質の最終確認は従来の品質工程で行います。

## 一括下書き

「複数コマの作画指示をまとめて準備」で正式・確定脚本から候補を作成します。登録名・承認済み別名の照合には既存の人物抽出を利用します。場所・時間帯・表情・ポーズ・構図・背景等はラベルで明記された値だけを転記します。自然文を解釈して情報を確定しません。画像アスペクト比は明記値と既存ページレイアウトの想定を区別して表示します。

候補一覧と原文・根拠を比較し、保存対象を選択して確認チェック後に保存します。既存指示は一括上書きできません。人物が一意でない・未登録・話者が不明なコマは一括保存せず、理由を表示します。「この下書きのコマを個別に確認・修正」から同じ画面の対象を開いてください。

下書き候補はセッション内の補助情報です。保存済み指示の正本はArtworkStoreのみです。再起動後は保存済み指示を再利用し、未保存候補は準備し直せます。途中保存に失敗した場合は保存済み対象を表示して保持し、残りを準備し直します。

## 再確認と安全性

- 脚本版変更時、旧版指示の自動再適用を禁止。原文と指示を照合した明示チェック後に保存し直します。脚本確定・人物バイブルの承認は別途必要です。
- 未保存の指示変更がある間、準備・画像取り込み・候補確認・採用を停止。入力を移動後も保持します。
- 一括保存は脚本版・人物UUID・作画revision・承認済み別名を再検査。保存中の競合も既存のArtworkStoreで拒否します。
- 対象確認票の完全一致、SHA検査、人間の確認と別操作の正式採用、保存復旧・差分更新を維持します。
- APIへの自動送信、GitHub作品同期、SNS投稿は実行しません。有料画像APIの本番送信は無効。予算は作品累計500円・全作品月間5,000円のままです。

## Macでの確認

Python 3.11または3.12で既存のセットアップを実行します。

```bash
git fetch origin
git switch feature/phase8-production-usability
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m streamlit run app.py
```

最初は既存作品のデータディレクトリをバックアップし、独立したテスト作品を使ってください。例えば、既存の無料検証スクリプトで新規データを作成できます（PDF・動画を含む自動検証なのでFFmpeg・ffprobeが必要です）。

```bash
python scripts/verify_production.py --output work/mac-phase8
MANGA_DATA_DIR="$PWD/work/mac-phase8/data/projects" python -m streamlit run app.py
```

作画指示が未登録の導線を確認するには、新規テスト作品に8ページ24コマの正式脚本を取り込み、人物・参照画像・バイブルを確認した上で、未制作コマを「画像制作 → このコマを制作」から開きます。既存の検証サンプルには指示が保存済みのものもあります。未登録状態を作るために既存作品のJSONを削除・編集しないでください。

STEP 2の未保存入力を残してホームへ移動・復帰し、保存後に準備ボタンが有効になること、異なるコマの確認票が拒否されること、確認保存だけでは採用されないこと、採用後に次コマへ進めることを確認します。脚本を新しい版として保存し、旧指示の再確認とバイブル再確認を要求することも確認してください。

## 操作手順

「企画・脚本 → AI企画・ストーリー」から次の順に進む。

1. 制作条件（テーマ・ページ数・企画件数等）を保存。
2. 手動 / 無料モック / 確認済み無料API / 有料APIを選択。既定は手動。APIではGeminiとOpenAIを明示選択する。
3. 使用モデル・送信対象・入力/出力上限・最大見積・作品/全作品月間残予算を確認。
4. 1送信だけを明示承認し生成。APIの場合、企画生成または初稿生成だけで停止する。
5. 企画カード・候補の本文・JSON・履歴を比較。企画の選択は正式脚本への採用とは別。
6. 評価・改善・再評価は、その都度「次の1送信」の内容・費用を確認して別承認する。無料モックだけは従来の最大5回改善を継続できる。
7. 人間が候補・差分・人物設定・後工程への影響を確認して脚本を採用し、「STEP 7」から最新脚本の正式確定画面へ進む。

手動モードのボタンから既存ChatGPT JSON取り込みへ移動できる。候補の不正JSONは応答を取得して手動取り込みで修正する。
自動の修復API・採用・脚本確定は行わない。正式採用は従来どおり新しい脚本版を追加し、画像・音声・動画の整合性を再確認する。

## 料金と無料APIモード

- 共通予算は作品累計500円 / 全作品月間5,000円のまま。
- モデル全入力幅を見積対象にし、平均token数・文字数による過小見積をしない。出力上限は256〜65,536 tokensで明示設定。ツール・検索・外部キャッシュ・バッチ・画像・音声を使わず、思考OFF。
- Geminiのひな形は公式参考単価のみ設定済み。確認日・為替・税の上限前提・利用確認フラグは未記入/falseなので、そのままでは送信できない。
- 例：入力全幅1,048,576、出力16,384、$0.10/$0.40、為替150円/USD、税係数1.10、安全係数1.25なら最大予約は**22.97856円/送信**。為替・税は説明用の仮定であり、本人が支払条件と上限を確認する。実使用が入力10,000/出力5,000なら保守換算約0.495円（安全係数を外して精算）。請求書の金額ではない。
- 無料枠をアプリから課金なしに証明できないため、**確認済み無料APIでも同じ正の最大額を予約し、usageを有料単価で保守換算して記録**する。無料枠を根拠に0円のPriceQuoteを作らず、BudgetedExecutorを迂回しない。これは無料枠の実請求が有料という意味ではない。
- 無料モードは本人によるfree_tier_reviewedと最近の確認日、通常の提供・権限・規約確認を必要とする。確認日が未来/2日以上前なら停止。無料枠を使い切った/条件が変わったら確認フラグを外す。無料から有料へアプリが切り替えることはない。
- 無料枠でも外部送信と枠消費には本人の個別承認が必要。無料枠の残量を常時監視する機能は未実装。送信後に利用条件が変わった場合の保証はしないため、各送信前に本人が確認する。
- 料金カードの提供・料金根拠は30日以内に更新する。Provider側の請求上限・支払設定と、アプリの共通予算は別々に管理する。

## MacでのAPI設定

既存のPython 3.11/3.12・Streamlit環境を利用する。追加のAI SDKは不要。通常のHTTPS通信なのでApple Silicon専用機能は使用しないが、Intel Mac/macOS 12実機でのAPI通信は未検証。

1. 対象アカウントでモデル提供、API権限、無料枠/課金プロジェクト、規約・データ利用条件を確認する。2.5モデルの利用権限がなければ手動/モックを使う。
2. キーをMacのターミナルで入力する（次はzsh用。値は履歴へ書き込まない）。共有画面・スクリーンショットへキーを映さない。

```zsh
read -s 'GEMINI_API_KEY?Gemini APIキー: '
export GEMINI_API_KEY
```

3. 無料確認済み経路の起動例：

```zsh
MANGA_ENABLE_TEXT_API=1 python -m streamlit run app.py --server.address 127.0.0.1
```

有料経路は、本人が支払設定・最大額・予算を確認した場合に限り、`MANGA_ENABLE_PAID_STORY=1`で起動する。フラグだけで送信は始まらない。
OpenAIの既存経路は`OPENAI_API_KEY`を環境変数へ設定する。キー値・部分文字列・長さ・ハッシュはUIや作品JSONに表示/保存しない。

4. 「Gemini料金設定のひな形」を取得し、公式根拠と本人確認に基づいて日付・為替・税・各確認フラグを記入。無料では適用・残枠・課金設定・データ条件を確認してfree_tier項目も記入する。キーをJSONへ入れない。
5. 制作条件画面でカードを確認・保存。今回の1送信の最大見積と残予算、送信内容を読んでから承認チェックと生成ボタンを押す。
6. 応答のJSON・人物・版・品質を確認。続行は別承認、正式採用と最終確定も別操作。

## 保存・安全境界・復旧

StoryAIService/AIStoryStoreの設定・企画セット・候補・評価・リクエスト・採用履歴を再利用する。新しい重複した正式脚本Storeは作らない。
既存schema_version=1のストーリーは維持。AI側の新provider、jobのaccess_modeと単発送信承認を追加し、旧データを初期化しない。
旧形式の複数回一括承認を持つ実APIジョブは、その承認を使って連続送信しない。必要なら新しい1送信依頼を明示作成する。

アダプターが予算実行context内で1回のclaimを取得し、検証済み本文のSHAをtransportへ渡す。HTTP側も送信先・model・同一本文と1回限りを確認する。
Responsesは発話に相当するrequest_idと入出力枠、Pollyはengineと最大文字数を照合する。直接呼び出し、同一contextの二重実行、別本文への差し替えを拒否する。
Pollyの有料音声も1発話ごとの承認に変更。無料モックの一括生成、VOICEVOX/WAVの候補確認フローは保持する。

承認は作品のrevision・現在phase・request_idに結び付ける。保存/請求が不明なら既存予約を保持し、自動再送しない。
応答とusageがあれば共有台帳で精算し、JSON不正でもそのAPI費用は消さず、正式採用を止める。
請求不明は予算画面で明細を本人が確認・照合し、その後「保存・請求状態の復旧」で既存応答を保存し直す。
受信前や応答保存前に失敗し結果が残っていない場合は、請求照合後に新規依頼として見積・承認し直す。自動再送や予約の自動解放はしない。

送信するのは作品条件、人物プロフィールと識別情報、確認済みバイブルの固定項目/別名/例外、選択参考技法、企画、対象脚本・評価のテキスト。
参照画像のバイナリや音声は送らない。人物の参照画像一覧/ローカルファイルパスはプロンプトから除く。APIキーはHTTP認証ヘッダーだけに使う。

AI JSONは送信用スキーマと既存のページ数・番号・描写・セリフ・ナレーション検証で照合する。未登録話者を警告し、名前・別名を照合する。
外見・衣装・性格との意味上の矛盾は自動保証せず、人間がバイブルと比較する。候補作成後の人物/バイブル変更は実API候補の採用を止める。
Gemini画像の本番送信停止、画像対象確認票、制作自動進行、PNG/PDF/MP4、同期仕様は維持する。自動同期やSNS投稿は追加しない。

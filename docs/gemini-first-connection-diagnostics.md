# Gemini初回接続診断

通信・請求が不明になった場合は[段階別ログと既存未確定分の安全な照合手順](gemini-diagnostic-recovery.md)を参照。

「企画・脚本 → AI企画・ストーリー → 制作条件 → Geminiの接続・無料枠・料金設定」に追加。
料金JSONを保存できる前から使える。**接続実装済み・実通信未検証**。Codexによる本物のGemini送信・無料枠消費・API費用はいずれも0。

## 最初に通信せず調べる

1. `GEMINI_API_KEY`を環境変数に設定し、アプリを起動する。UIへキーを貼り付けない。
2. Gemini設定JSONを選択/貼り付ける。未入力、不正JSON、確認フラグfalseの状態でもよい。
3. 「通信なしで設定を診断する」を押す。

確認するのはAPIキーの設定有無・ローカルな形式、JSON形式、同梱公式モデル情報、料金・利用条件の不足、本人の無料枠/権限確認状況。
APIキーで認証できるか、モデルを使えるか、無料枠が本当に適用されるかは確認しない。
この操作はHTTP送信・予算DBの作成/読込/予約・作品保存をしない。表示だけで確認フラグや料金JSONを書き換えない。
入力を変更した場合はもう一度押して診断する。結果は現在のブラウザセッションにだけ保持する。

|表示|意味|
|---|---|
|未確認|その確認が未記入、期限切れ、または証拠がない|
|確認済み（本人申告）|利用者がJSONに確認を記録した。アプリが通信で検証したという意味ではない|
|公式モデル情報の確認済み|2026-10-26時点の同梱資料とIDの一致。現在の提供・対象アカウントの権限の証明ではない|
|通信成功（診断時点）|承認された診断で正しいモデル・JSON応答・usageを確認した。無料枠や継続的な利用可否は別|
|利用不可・再確認|その診断を受け付けられなかった。429等は一時的な枠・容量不足の可能性もある|
|結果確認待ち|通信・応答・利用量・保存結果が不明。請求照合まで再送しない|

AI Studioに無料枠が表示されていても、特定モデルを使えることの証明にはしない。
キーの値・部分文字列・長さ・キーのハッシュは表示/保存しない。過去の通信成功を現在のキーに自動で結び付けない。

## 料金と利用条件を確認した後、実通信を1回だけ承認する

診断前に通常生成用JSONを保存する必要はない。**account_access_reviewedはfalseのまま**で診断できる。
ただし、他の確認・料金項目を未確認のまま送信できるわけではない。

- `availability_reviewed`：公式モデルの提供案内を本人が確認。アカウント権限の確認とは別。
- `structured_outputs_reviewed`：診断で使うJSON出力等のAPI仕様を確認。
- `commercial_use_reviewed` / `external_data_reviewed`：利用目的・規約・外部送信とデータ利用条件を確認。
- `maximum_billing_reviewed`：料金、モデルの最大入力幅、出力上限、追加機能不使用、最大料金を確認。
- `verified_on`、入力/出力単価、`fx_jpy_per_usd`、`tax_multiplier`、`safety_multiplier`、`tax_note`：最新公式料金と本人の支払条件で設定。料金確認は30日以内。

未確認の項目を診断のために確認済みと偽らない。キーをJSONへ入れない。
既存ひな形のモデルIDは`gemini-2.5-flash-lite`。公式には過去利用者へのアクセス制限の案内があるため、403/404なら対象プロジェクトの条件を確認する。
公式情報：[モデル](https://ai.google.dev/gemini-api/docs/models/gemini-2.5-flash-lite)、[料金](https://ai.google.dev/gemini-api/docs/pricing)、[API](https://ai.google.dev/api/generate-content)、[規約](https://ai.google.dev/gemini-api/terms)。
既存の[Phase 9-B2確認記録](phase9b2-text-ai.md)・料金ひな形を再利用する。今回、新しい料金や利用権限を実通信で確認してはいない。

利用モード：

|モード|条件|
|---|---|
|課金の可能性あり・最大額を承認して診断|無料枠適用が不明でも、本人が有料になる可能性と最大額を承認する。`MANGA_ENABLE_PAID_STORY=1`が必要|
|無料枠は本人確認済み・モデル権限は診断で確認|本人が適用・残枠・課金設定・データ条件を確認し、`free_tier_reviewed`と最近の確認日を記録。`MANGA_ENABLE_TEXT_API=1`が必要。モデル権限はまだ未確認でよい|

どちらも正の有料上限で予算予約し、usageを保守的な有料単価で精算する。無料枠から有料へ自動切替しない。
両フラグは既定OFF。フラグだけでは通信を始めない。今回のモード・料金確認・送信範囲・共有残予算を見た上で、毎回別の承認チェックと実行ボタンを押す。
UIにモデル、最大入力1,048,576 tokens、最大出力256 tokens、最大費用、作品残額、全作品月間残額、固定文を表示する。

送る本文は次だけ：

```text
Connection diagnostic only. Return exactly this JSON: {"ok":true}
```

作品・脚本・人物・バイブル・参照画像・音声は送らない。APIキーは認証ヘッダーにのみ使う。
ツール・検索・外部キャッシュ・思考・複数候補・モデル自動切替・自動再試行は使わない。
最大費用は文字数から小さく推測せず、従来どおりモデル全入力幅で保守的に算出する。
公式参考単価の入力$0.10/出力$0.40（100万tokensあたり）、仮の為替150円/USD・税1.10・安全係数1.25なら、診断の最大予約は**21.648円**。
これは説明用前提で、実請求や無料枠の保証ではない。実使用は返されたusageで保守換算して記録する。

## 診断結果への対応

- **403**：キー/プロジェクトの権限、キー制限、地域・組織ポリシー、モデルの提供条件等を確認する。原因を一つに断定しない。
- **404**：モデルID、現在の提供状況、アカウントから見えるモデルを確認する。別モデルへ自動変更しない。
- **429**：利用回数/トークン/無料枠/一時容量の上限等を確認する。有料切替・自動再送をしない。
- **401**：Macのキー設定と発行プロジェクトを確認する。キーを画面や問い合わせ本文へ貼り付けない。
- **400・5xx・通信失敗・不正応答**：API仕様・ネットワーク・提供元の利用履歴・請求を確認する。応答モデル/usageが不明なら成功と表示しない。

エラーの分類にはHTTPステータス等の固定値だけを使う。エラー本文・URL・ヘッダー・例外の生の文字列を履歴へ保存/表示しない。
診断成功でも無料枠の確認状態と通常生成用の利用権限フラグは変えない。本人が利用条件を確認できた場合だけ、JSONの該当項目を明示更新し、従来の保存操作で通常生成用設定を保存する。
JSONの保存・脚本生成・企画選択・脚本正式採用/確定はそれぞれ別の操作である。

## 予算・二重送信・保存復旧

BudgetedExecutor / BudgetLedgerをそのまま使用し、作品累計500円・全作品月間5,000円を維持する。
診断もprovider=`gemini-text`に算入するため、通常のGeminiとプロバイダー別予算を分離して迂回しない。
診断用PriceQuoteには固定本文のSHA制約があり、共通の実行権でもその制約を照合する。診断用見積を使って脚本や別の文章を送信することはできない。
通常生成用quoteの権限チェックは緩めず、診断用quoteに限ってアカウント利用権限の未確認を許容する。

承認は作品・設定JSON・モード・固定本文・保存revisionと結び付け、送信前に処理中イベントを保存する。
既存AIStoryStoreのイベント/不変ファイル、世代ロック、共有台帳の永続claimとHTTPの単発送信権を使用する。
新しい重複した正本やトップレベルJSONスキーマは作らない。通常生成の候補/採用や設定を診断で変更しない。

アプリ終了や保存失敗後は同じ診断IDで「診断の保存・請求を照合する（再送なし）」を使用する。
HTTP拒否でも予約を自動解放しない。請求不明は共有予算画面で本人が明細を照合し、無課金なら既存の無課金照合を行う。
照合後、応答があれば保存を再開する。応答がなければ通信成功とはせず、履歴を残して新しい診断を個別承認できる状態にする。
台帳に実行記録がなく送信前停止と確認できた場合も、履歴を残して新しい見積へ進める。
履歴と異なる台帳への切替や、請求不明のままの新規送信を拒否する。台帳・履歴を削除して0円から再開しない。

テストはすべてフェイク・オフライン。実キーでの認証、実モデル権限、実無料枠、最終請求、Mac実機は未検証。
既存の脚本生成、無料モック、音声、画像API停止、対象確認票、PNG/PDF/MP4、自動進行、GitHub同期は維持する。

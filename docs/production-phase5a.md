# Phase 5-A：制作ダッシュボードと手動画像制作

ホームの9工程は、作品ごとの既存Storeから毎回再構築する。チェックボックスを押しただけでは完了にならない。`未着手 / 進行中 / 要確認 / 完了`、有効な成果物数、足りない条件、次の操作、制作画面への移動を表示する。

## 制作の手順

1. プロジェクト管理で企画を保存する。AI企画候補からの採用、または既存のJSON取り込みで正式脚本を保存する。
2. 「比較・脚本確定」で最新の脚本版を明示確定する。同じ本文でも新しい版を取り込むと再確定が必要。
3. キャラクター設定・基準画像・キャラクターバイブルを確認する。基準画像のない人物は、バイブルを保存後、手動画像制作で「人物の基準画像」を選べる。画像の採用後にバイブルを再確認する。
4. 作画指示に登場人物UUIDを設定する。ホームの不足理由から、話者の不一致・固定設定の矛盾・古い脚本版を修正する。
5. ホームの未完成コマ、または「イラスト制作 → 手動画像制作」を開く。「この対象のプロンプトと基準画像を準備」でプロンプトをコピーし、必要な基準画像PNGと対象確認票JSONを取得する。ChatGPT等へ自分で添付する。
6. 生成画像と**生成時の対象確認票**を手動画像制作にアップロードする。ページ番号・コマ番号・人物UUID・バイブルID・脚本版・プロンプトハッシュ・素材トークンが一致しなければ受け付けない。確認票は画像の内容を証明しないため、人間が候補の外見・構図・権利を確認し、別操作で正式採用する。
7. 漫画ページ編集で各ページの配置・読み順を保存し、PNG・PDF書き出しで「全ページPNG（ZIP）」と「全ページPDF」を生成する。PNGだけ、PDFだけ、標準の仮配置だけ、未採用画像がある状態では工程を完了にしない。
8. 音声制作・字幕で**無料モック**の声設定を保存し、音声を生成・試聴する。タイムラインJSONとSRTを保存する。モックは日本語音声ではなくトーンであり、音声の完成品質は要確認として残る。
9. 動画制作でYouTube本編・TikTok縦型・YouTube Shortsの独立計画を保存し、既存FFmpegで3形式を出力する。ホームの「保存済みの音声・字幕・動画を検証」でハッシュ・SRT・WAV実尺・最新タイムライン・動画計画・H.264/AAC MP4を照合する。
10. 既存の品質チェック・修正管理で自動検査、プレビュー、ページごとの目視確認、修正タスクの解消、最終確認を行う。すべての必要条件がそろった後、ホームで完成品・素材権利の最終確認を保存する。

## 保存と再開

| 正本 | 利用内容 |
|---|---|
| ProjectStore / StoryStore / EditorialStore | 作品・正式脚本の履歴・最新脚本版の確定 |
| ArtworkStore / CharacterAIStore | 人物UUID・基準画像・バイブル・作画指示・採用画像 |
| ImageAIStore | 手動入力原本・候補・目視と権利の確認・明示採用・既存の採用復旧 |
| PageStore / StudioStore | ページ構成・既存の描画/出力記録・保存済みページ出力 |
| VoiceStore / VideoStore | 声設定・WAV・SRT/タイムライン・計画・MP4・検証と最終確認の証跡 |
| ReviewStore | 既存の自動検査・ページごとの目視/最終確認・修正タスク |

進捗専用の別JSONは作らない。`studio.json` の新しい出力イベントには任意項目 `path / sha256 / bytes / sns_width` を付加し、`studio_exports/<SHA>.<拡張子>` に実体を保持する。旧イベントは引き続き読めるが、実体がない旧生成記録だけでは出力完了にしない。

出力は排他的なハードリンクとfsyncで保存する。同一の保存条件では検証済み出力を再利用する。実体保存後にメタデータ保存が失敗しても、同じ処理で再試行できる。元の画像、脚本、人物、音声、動画、過去の出力を削除しない。画像候補・採用の保存中断は既存ImageAIServiceの同じジョブID/画像IDの復旧を使用する。

音声・動画の全ファイル検証は利用者の明示操作時に実行する。`VideoStore.events` の `production_validation` に検証証跡、`production_final_review` に完成品の人間による確認を追記する。検証対象の設定とファイルstat（inode、容量、mtime、ctime等）が変われば、以前の証跡を現在の完了判定には使わない。ホームの通常表示では原寸画像を全件復号しない。これはローカルの更新検知であり、管理権限を持つ第三者による意図的な改ざんの証明ではない。

脚本を変更しても旧素材は残し、作画指示・画像・バイブル・ページ・音声・動画の再確認へ誘導する。保存途中や実行中の処理がある場合は、新しい制作より先に既存の復旧画面へ移動できる。

## GitHub作品同期

既存の同期対象・manifest・作品ID・採用仕様を変更しない。新しい `studio_exports` はローカル再利用用であり、自動でGitHubへ送信しない。PNG/PDFを同期する場合は、従来どおり書き出し画面の「この完成ファイルをGitHub同期用にローカル保存」を押し、GitHub作品同期画面で対象を選択する。音声・動画の重いバイナリもソースブランチに追加しない。復元先にローカル出力の実体がなければダッシュボードは不足と表示する。

## Macでの動作確認

リポジトリ直下で実行する。既存データ領域を変更せず、まず新しい検証作品を利用する。

```bash
git fetch origin
git switch feature/phase5a-production-dashboard
python3.11 -m venv work/mac-venv
source work/mac-venv/bin/activate
python -m pip install -r requirements-dev.txt
brew install ffmpeg
python -m pytest -q
python scripts/verify_production.py --output work/mac-phase5a-demo
MANGA_DATA_DIR="$PWD/work/mac-phase5a-demo/data/projects" python -m streamlit run app.py
```

Python 3.12では別venvで同じ全pytestを実行する。検証スクリプトの出力先は**存在しないディレクトリ**を指定する。同じ出力先の再実行は上書きせず停止する。Macの日本語フォントは既存のヒラギノ検出を利用し、必要なら既存設定の `MANGA_FONT_PATH` を指定する。ローカル保存先にはファイルロック・ハードリンク・十分な空き容量が必要。

作品を開き、ホームから未完成工程へ移動できること、手動画像制作で確認票を取り違えると拒否されること、候補の確認前には採用できないこと、再起動してPNG/PDFと履歴を再取得できることを確認する。画像候補や脚本を変更後、古い成果物が要確認になることも確認する。

## 自動検証と人間の確認

`scripts/verify_production.py` は独立した8ページ24コマを、無料の企画・脚本モック → 正式採用と脚本確定 → 人物とバイブル → 基準画像・全コマ画像の手動入力 → ページ構成保存 → PNG ZIP/PDF → 無料トーン・SRT → 3形式の実MP4まで処理する。ネットワーク・課金ゲート・有料音声アダプターの実行を拒否し、同じ音声と動画の再利用も検証する。権利・外見の確認操作はテスト内で模擬するため、人間が確認した事実として報告しない。

短いテスト用MP4の音声トーンと焼込字幕をデコードして開始誤差を測定し、許容250ms以内を確認する。YouTube本編のテスト動画にも全24コマを含めるが、公開向けの目標尺に引き伸ばさない。テスト画像・モック音声・未完了の品質レビューが残るため、全工程を緑にしないことが期待結果。

人間が行うのは、人物の外見と連続性、漫画の読み順とセリフ配置、日本語の発音と演技、字幕の意味、映像の見切れと編集、全素材の権利、公開先ポリシーの最終確認。Intel Mac実機および実際のChatGPT生成画像の品質はクラウドpytestでは検証できない。

## 安全性とPhase 5-B

有料画像APIは既存の無効状態を維持する。共通予算の作品生涯500円・全作品月間5,000円、既存のfail-closedガードは変更しない。このPhaseの開発・自動テストの実課金API呼び出しと費用は0回・0円。

次のPhaseで自動化できる候補は、未完成工程への順次案内、確認票と素材の一括整理、ページ/動画の差分に限定した再出力、無料の日本語音声エンジンまたは許諾済み音声の取り込みと同期検証。画像APIの本番送信は最大請求量・料金根拠・同意・予算ゲートを満たす別開発が必要。外見の一致、創作品質、素材権利、公開の最終判断は人間の確認として残す。

# Phase 11：ホームから漫画PNG・PDFまで

2026-10-28確認。PR Aの画像契約・予算・単発送信の上に、PR Bで既存の漫画MVPを接続する。実APIの通信は開発中0回。フェイク画像の一致・画質・権利・公開可否は保証しない。

## 再利用した正本と処理

企画・脚本はStoryAIService、人物はCharacterAIService、画像はImageAIService、構図・セリフはPageStore、PNG/PDF/ZIPはAutomationと既存Studio出力を使う。API費用は既存BudgetLedgerだけに記録する。StudioのMVP記録は承認範囲・実行履歴・停止位置であり、素材の重複した正本を作らない。旧MVP記録の形式・UUID・履歴を変更しない。

新規作品だけが対象。既存作品を「漫画を制作」で上書きしない。別工程で素材を変更した場合、再検査まで停止する。画像・採用・出力履歴を削除しない。画像差し替えは既存の手動取り込み・候補確認・正式採用を利用する。

## 操作と停止位置

1. ホームの「テーマから新しい漫画を制作」でテーマ・ジャンル・ページ数・画風・テキストAI・画像AI・品質・最大予算を設定する。
2. テキスト送信と、新規作品の一意な人物登録・制作脚本保存の範囲を確認して「漫画を制作」。実APIの評価・改善を追加で自動送信しない。
3. 人物・バイブルが準備されると初回画像1枚で停止する。モデル・全対象・参照画像・プロンプト・保存先・最大予約額を確認して承認する。
4. 最初の画像を目視・権利確認し、確認記録を保存する。usage・精算・保存を確認して「初回1枚の確認を記録」。確認と正式採用は別操作。
5. 残りの基準画像を再見積して承認する。人物数が2名なら残り1枚。基準画像を確認し、制作再開で既存の正式採用・バイブル更新へ進む。
6. 作画指示・ページ配置を既存Serviceで保存後、未完成コマだけを最大24件ずつ再見積する。全対象の承認後、各1回だけ順番に生成する。
7. 候補をまとめて確認し、制作再開で採用・セリフ合成・8ページPNG・PDF・PNG ZIP出力へ進む。

人物の同定が曖昧、作画指示不足、参照画像欠損、ハッシュ変更、上限超過、利用条件未確認、請求不明、保存失敗では停止する。公開品質の判断は人間に残る。動画・音声・GitHub同期・SNS投稿は追加実行しない。

## 費用と承認

料金の公式根拠・上限の計算式は[画像APIの設計](phase11-image-api.md)を参照。画像に無料API枠はない。テキストの無料枠を画像に流用しない。

仮の上限為替150円/USD・税1.10・安全係数1.25なら、標準1K/思考minimal/合計出力上限2,048で1枚最大16.051200円、基準2枚+24コマ最大417.331200円。高い思考上限4,096では26枚746.803200円となり作品500円を超える。画像出力部分だけの価格$0.0336を最大請求額として使わない。

テキスト3送信と画像26枚の全最大予約額は500円を超える場合がある。そのため、最初のテキスト範囲の承認は画像を許可しない。テキストが精算された後に画像を再見積し、共通残額に収まる場合だけ追加承認できる。実際の人物数・ページ数・既存画像数によって枚数は変わる。ユーザー指定の作品上限も送信ごとに検査する。26枚が常に500円以内で完成するという保証はしない。

一括承認は対象・材料版・プロンプトSHA・参照画像ID/人物UUID/SHA・料金カード・台帳・件数・上限を固定する。全件を別予算へ移したり、未使用枠を別画像へ使い回したりしない。各送信前に既存台帳へ予約し、共通予算の競合があれば次の送信前に止める。

## 停止と再開

- アプリ終了後は同じ作品を開く。候補と出力の正本から次の処理を判定し、完成済み画像・PNG/PDFを再利用する。
- queuedの同じ依頼は同じrequest_idで実行。送信済み依頼は再送しない。
- 通信結果不明・usage欠落・モデル不一致は予約保持。ホームの共通予算リンクから、Google側の請求と手動照合する。データなしを0円の証明にしない。
- 精算済みで応答保存済みなら「保存だけを復旧」で同じ候補IDへ復旧できる。画像の再生成は行わない。usageと精算が合わなければ復旧も停止する。
- 応答や料金が不明なまま次の画像を作成しない。自動リトライ・モデル変更・高品質への自動昇格は行わない。
- 失敗した同一対象を新しい依頼で自動迂回しない。必要なら既存の手動画像で差し替え、素材の再検査を行う。

## Macの最小実機テスト（1作品）

事前にDB・作品フォルダーをバックアップし、PR A/Bの両方を取り込んだブランチを使用する。Macでは既存のPython3.11/3.12環境・日本語フォント・FFmpeg設定を維持する。既存のGeminiテキスト接続・料金設定を再利用する。

```bash
python -m pip install -r requirements-dev.txt
export MANGA_ENABLE_TEXT_API=1
export MANGA_ENABLE_GEMINI_LITE_IMAGE=1
python -m streamlit run app.py
```

APIキーは既存の安全な環境変数GEMINI_API_KEYで設定する。キーをコマンド例・JSON・画面・PRへ貼らない。上のフラグだけで送信されることはなく、画像料金とアカウント・送信条件の確認、対象ごとの承認が必要。旧画像モデルの本番停止フラグは変更しない。

ホームで新規8ページ、人物2名を想定したテーマ、Gemini3.5テキスト、Gemini Lite Image・標準品質・最大500円を選択する。料金・利用権・外部送信条件を本人が確認し、まず1枚だけ承認する。実際の画像・usage・精算を確認できた場合に残りの基準画像、続いて24コマを承認する。途中でアプリを再起動しても同じ作品から再開し、完成済み画像数が増えず再利用されることを確認する。最後にPNG8枚・PDF8ページ・ZIPをダウンロードし、人物・セリフ・順序・余白・権利を1作品で確認する。請求不明があればそこで終了し、照合まで送信を再開しない。

## 自動テストと未確認事項

新規テストはHTTP禁止のフェイクで単発・参照画像・26画像・24コマ・UUID/SHA・PNG/PDF・上限・中断・保存復旧・再起動・二重送信・Streamlitの承認操作を検証する。既存の無料モック・手動制作・音声/動画・共通予算のテストも全件実行する。

実際のGoogle応答のusage、権限、課金、画像品質、人物一致、Intel Mac上での実行は未検証。未確認の応答形式は予約保持で停止する。モデル提供状況・料金根拠は期限内の確認が必要。無人で公開可能な作品を保証する機能ではない。

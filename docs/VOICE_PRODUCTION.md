# キャラクター別音声・字幕の操作ガイド（Phase 3）

既存の6工程を維持し、**完成・書き出し → 音声制作・字幕**を追加しました。
初期状態はAPIなしの確認用モックです。生成されるのは長さの異なるトーンで、日本語の人声ではありません。
漫画のストーリー・人物ID・参照画像・作画指示・ページ設定は変更しません。

## まず無料で動作を確認する

1. 作品を選択し、保存済みストーリーと人物設定を用意します。
2. 「準備・話者設定」で各人物とナレーターの声を設定して保存します。モックには4種類の確認用トーンがあります。
3. 「音声生成・試聴」で対象ページ／全ページを選びます。話者が不明な発話は、人物・読み上げ文・感情を確認して保存します。元の脚本は書き換えません。
4. 対象発話を選択し、見積を確認して生成します。同一内容の保存音声は再利用します。試聴・WAVのダウンロード・人間による確認記録ができます。
5. 「字幕・タイムライン」で余韻と無音コマの表示時間を設定し、新しい版として保存します。JSONとSRTをダウンロードできます。
6. 「履歴・復旧」で過去の音声候補を確認できます。現在の発話・声設定と一致する候補だけを再採用できます。

ナレーション→そのコマのセリフの順で抽出します。名前は既存人物IDへ対応付けます。
名前の重複・不明な話者・分割できないセリフは推測で割り当てません。画面で明示的に確認してください。
通常・怒り・悲しみ・ささやきを発話ごとに指定でき、読みだけを変更することもできます。
声・読み・感情・速度を変えた発話だけが新しい生成対象になります。作品全体の脚本版変更で、無変更の全音声を作り直しません。
「再生成」は保存済み音声があっても新規生成する操作で、有料モードでは再課金対象です。

## 有料TTSを利用する前の条件

**今回の開発では有料実呼び出しを承認・実施していません。以下は承認後の利用手順です。**

最初の接続先はAmazon Pollyです。[公式比較・価格](tts-provider-comparison.md)を確認してください。
StandardのMizuki/Takumi、NeuralのTakumi/Kazuha/Tomokoを選択できます。声の無断クローンはありません。
怒り・悲しみは速度・音量の演技設定です。Standardのささやきは専用SSML、Neuralは小声の近似で、試聴確認が必要です。

有料生成には次の条件がすべて必要です。

- 現在の脚本版が「比較・脚本確定」で人間により確定済み。
- 公式料金・日本語・商用利用条件・最大請求量を人間が確認した、有効期限30日以内の料金設定。
- 別途の有料利用承認と、環境変数 `MANGA_ENABLE_PAID_TTS=1`。設定しなければ有料処理は停止します。
- AWS認証情報を実行環境から取得できること。`AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、必要なら `AWS_SESSION_TOKEN`、リージョンは `AWS_REGION`（既定 `ap-northeast-1`）。ソース・JSON・GitHub・ログへ保存しません。
- 対象・版・設定・上限見積に対する、その都度の画面上の明示的な同意。
- 共有予算台帳の作品生涯500円・全作品月間5,000円に余裕があり、請求不明などの停止条件がないこと。

料金設定は「準備・話者設定」の詳細にあります。入力の既定はJSONファイルです。
未記入テンプレートと [確認日付きの例](../examples/voice/pricing_20261024.json) は、確認フラグをすべてfalseにして配布します。
単価・為替上限・税・安全係数・確認日を自分の利用条件に合わせて確認し、JSONの `commercial_use_reviewed`、`japanese_reviewed`、`billing_maximum_reviewed` を確認後にtrueへ変更します。
さらに画面の確認チェックを入れて保存してください。料金設定の保存や声の選択だけではAPIを送信しません。
為替は自動取得しません。例の160円/USDは仮定です。未知の費用がある場合は有料設定を承認しないでください。

AWS契約のデータ利用条件も確認してください。未公開の脚本を外部へ送信する点は、ローカルのモックと異なります。

## 保存・キャッシュ・途中失敗

作品フォルダ内に独立した `voice.json` と `voice/` を保存します。

| 保存先 | 内容 |
| --- | --- |
| voice.json | 声設定と版、読みの編集、生成ジョブ、採用対応、試聴確認、料金根拠、出力履歴、イベント履歴 |
| voice/audio/UUID.wav | 元音声を変更しない候補履歴。16bit PCM、16kHz、モノラル |
| voice/staging/ | 応答の保存記録とWAV。課金後の保存再開に使うため自動削除しない |
| voice/exports/UUID.json・.srt | 保存時点のタイムラインと字幕。過去版を上書きしない |

キャッシュはNFC正規化した読み・人物ID・プロバイダー・声・engine・速度・感情・音声形式版のSHA-256です。
脚本の元本文と版IDは生成元として別に保持します。同じキャッシュキーでも、ファイル欠損・SHA不一致なら成功扱いにしません。
`revision` の照合とファイルロックで保存競合を停止します。生成も作品ごとに直列化し、並行実行による二重課金を防ぎます。

タイムアウト・応答利用量欠落では自動再送せず、ジョブと予算予約を残します。
「API予算管理」で実際の明細を手動照合し、精算後、保存済み応答があれば「履歴・復旧 → 音声保存を再開」で追加送信なしに復旧します。
保存先の空き容量・ハードリンクを送信前に確認しますが、応答をディスクへ保存する前に故障した場合は音声を復元できないことがあります。
請求を照合したうえで「この未完了ジョブを履歴に残して終了」を明示的に選び、新規生成が必要か判断してください。終了しても課金実績・履歴は消しません。
生成途中で予算DBのパスを変更して、0円からやり直すことはできません。元の共有台帳を復元してください。

作品フォルダ全体と、別管理の予算DB・初期化記録を、全アプリ停止後にバックアップします。
音声ファイルをソースブランチへ自動追加したり、既存GitHub作品同期の対象へ一括追加したりしません。

## Macで更新する

レビュー・マージ後、Gitで導入している場合は次を実行します。
先にアプリを終了し、作品と予算台帳をバックアップしてください。

```bash
cd /実際の保存場所/manga
git switch main
git pull --ff-only
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

Python 3.11を推奨します。`requirements.txt` がない場合は、まず `pwd` と `ls` で `app.py` と同じディレクトリにいるか確認してください。
ZIPの場合はデータを含む旧フォルダを残し、新しいフォルダで仮想環境を作って起動します。
`MANGA_DATA_DIR` と `MANGA_BUDGET_DB` は更新前と同じ外部保存先を指定します。コード更新は作品データの自動移動を行いません。
追加pip依存はありません。ffprobeがあればWAV実尺を照合し、不在でもPCMフレーム数から正確に計測します。動画生成は [Phase 4の任意画面](VIDEO_RENDERING.md) から使います。

## データに触れずに無料検証する

```bash
python scripts/verify_voice.py --output /tmp/manga-voice-new-demo
```

未作成の出力先を指定します。3人物＋ナレーター、8ページ24コマ、5発話を含む専用作品を新規作成し、生成→5件キャッシュ→変更1件だけ再生成→JSON/SRT保存を検証します。
既存フォルダを上書きしません。生成物は日本語音声ではなくテスト用トーンで、API呼び出し0回です。
JSONとWAVの次工程向け仕様は [VOICE_TIMELINE.md](VOICE_TIMELINE.md) を参照してください。

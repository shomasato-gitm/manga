# AI企画・ストーリースタジオ（Phase 2-A/B）

**企画・ストーリー → AI企画・ストーリー**を追加しました。既存の6工程・手動ChatGPT連携・ページ編集・評価・履歴は残しています。
初期状態は無料モックです。有料APIは別途の明示承認まで使用しません。今回の開発・CIで有料APIを呼び出していません。

## 無料で一連の操作を確認する

1. プロジェクトを作成・選択し、AI企画・ストーリーを開きます。生成方法は「無料モック」のままにします。
2. 「制作条件」でジャンル、テーマ、ページ数、雰囲気、企画案3〜5件を入力します。自動改善の上限は0〜5回、目標点は既定85点です。
3. 「総合点または評価項目が低下したら停止」は既定オンです。必要なら参考作品を3件まで選び、条件を保存します。
4. 「企画案の生成・比較」で見積を確認し「企画案を自動生成」を押します。「状態を更新」で完了を確認します。
5. タイトル、ログライン、葛藤、転換点、結末、独自性、懸念点を比較し、1案を明示選択します。選ばない案も消えません。
6. 「脚本制作・自動改善」で開始します。初稿→評価→改善→再評価を上限まで実行します。
7. 「比較・採用・履歴」で版別得点、8項目の差、実際のJSON差分、改善理由、ページの引き、コマ・セリフを確認します。
8. 任意の候補を選び、確認チェック後に「正式脚本の新しい版として採用」を押します。自動推薦された候補も、自動で正式採用はしません。
9. 従来の「比較・脚本確定」で人間が確定し、人物・作画工程へ進みます。

モックは保存・検証・予算境界の動作確認用です。繰り返す場面や決定的な点数を含み、実モデルの日本語脚本品質を示しません。
実APIもモックも同じ検証器・候補保存・評価・正式採用経路を通します。
各ページ約3コマを基本にし、全ページ・コマの情景・話者付きセリフ・ナレーションをschema_version:1へ正規化します。
ページの引きは独立メタデータとして保存し、旧ストーリーJSONの項目を増やしません。

企画条件は専用保存です。プロジェクト設定は自動変更しません。
候補ページ数をプロジェクトと変えた場合、正式採用前に「プロジェクト管理」でページ数を合わせてください。
登録人物のID・外見設定を入力資料として維持します。新しい人物は自動登録せず、参照画像の実データもテキストAPIへ送信しません。
参考作品は登録要約から抽象化した技法だけを利用し、スクレイピング・既存作品のセリフ等の模倣は行いません。

## 自動改善の停止条件

- 目標点への到達。点数だけで脚本確定・公開許可にはしません。
- 指定上限への到達。最大5回はアプリ側でも検証し、6回目を自動送信しません。
- 総合点または8項目のいずれかの低下（既定オン）。低下版も残しますが、前の推薦候補を維持して停止します。
- JSON構造上の脚本変更がない場合。
- 各呼出しの最大見積を依頼・作品・月間の残額で確保できない場合。
- 元の作品・人物・脚本・参考情報の変更、API拒否／未完了／不正JSON、請求不明、保存先エラー。
- 利用者の停止要求。開始済みの1回は応答と課金状態を保全し、次の呼出しを止めます。

評価は導入、人物、構成、感情、セリフ、伏線、結末、独自性の8項目・各10点です。動機や矛盾も評価プロンプトへ含めます。
総合点はアプリが合計÷80×100で再計算します。AIの自己評価は主観的な参考値で、改善や品質を保証しません。
人間は低下版・未評価版も、警告と差分を確認したうえで明示採用できます。

## モデル・料金と承認

[公式比較](story-ai-provider-comparison.md) を参照してください。最初のアダプターはOpenAI Responsesです。
モデルID・許容する応答モデルID・単価・入力／出力の上限・確認日・為替・税・安全係数をJSON設定へ保存します。
モデル名・料金を製品コードに固定していません。モデル昇格、検索、ツール、トークン計数API、追加プロバイダーへの自動切り替えはありません。

有料利用には、すべて必要です。

- 別途の有料利用承認と、`MANGA_ENABLE_PAID_STORY=1`。
- `OPENAI_API_KEY`を実行環境へ安全に注入。ソース・作品JSON・GitHub・ログへ保存しません。
- 公式モデルの提供・Structured Outputs・商用条件・モデル最大入力幅・すべての加算料金を人間が確認した、30日以内の料金カード。
- 見積・対象・制作条件・実行上限に対する、その都度の確認チェック。承認範囲のハッシュ・日時を依頼履歴へ記録します。
- 共通BudgetedExecutorと同じ永続SQLiteを利用し、作品生涯500円／全作品月間5,000円と依頼単位の上限に余裕があること。

「制作条件」の詳細から料金テンプレートまたは [公式確認日付きの設定例](../examples/story_ai/pricing_20261024.json) を取得します。
例は確認フラグをすべてfalseで配布します。自分の契約と公式条件を確認して値を調整し、確認後にフラグをtrueへ変更して取り込みます。
取り込みの初期値はJSONファイルです。保存しただけではAPIを送信しません。キーをJSONへ追加すると拒否します。

### 見積の意味

入力tokenを文字数÷4等の平均だけで見積もらず、公式モデルの最大入力token数全体で予約します。
出力上限には不可視のreasoningも含みます。長文・キャッシュ書込なども含む安全側の単価を指定します。
設定例では単発最大107.908064円、企画から改善5回まで13呼出しの理論最大1,402.804832円です。
仮定は160円/USD・税1.10・安全係数1.25で、実為替を取得した値ではありません。

**理論最大額と実行上限は別です。** 500円枠を超える全工程の完走を保証せず、各呼出し前に残額を確認して停止できます。
実際の入力が短くても、次の最大予約額を確保できなければ送信しません。
精算は応答token数に安全側単価と設定為替・税を適用した予算上の換算です。割引後の請求書や実決済額ではありません。
公式上限と異なるusageが返った場合、超過実績を隠さず記録し、新規実行を停止します。
APIキー未設定・未承認の実費試験は行いません。モデルの日本語品質・実際の請求は別途確認が必要です。

## 保存・再実行・復旧

| 保存先（作品フォルダ内） | 内容 |
| --- | --- |
| story_ai.json | 制作条件・料金カード、企画セットと選択履歴、候補脚本・評価、ジョブ・リクエスト、採用の対応、イベント |
| story_ai/responses/REQUEST_ID.json | 見える応答本文・usage・モデル等の保存。認証ヘッダーやエラー原文・内部reasoning本文は保存しない |
| story_ai/jobs/ | 保存試験・停止要求の記録。API呼出しごとに永続UUIDを使用 |
| story_ai/adoption_pending.json | 正式採用の前後スナップショットと再開記録 |
| story_ai/adoptions/ | 完了した採用記録の履歴 |

企画／候補は確定データと別です。候補の採用時だけ、既存StoryStoreが読める新しい版をstory_history.jsonへ追記し、その候補の評価を正式版IDへ対応させeditorial.jsonへ追記します。
以前の脚本・評価・人物・画像・作画指示・音声・動画は削除しません。ページの引き・改善元・企画IDなどは専用ファイルで追跡します。

同条件の依頼を再度開始すると保存済みジョブを再利用します。「新規に作り直す」は明示的な別リクエストで、有料では再課金対象です。
途中失敗の同じrequest_idを自動再送しません。タイムアウト・usage不明は予約を保持します。
「進行状況 → 保存・請求状態の復旧」を使用し、請求不明ならAPI予算管理で明細を照合してください。
精算済み応答が保存されていればAPIなしで候補保存を再開できます。応答が失われた場合は自動生成し直しません。
不正JSON・拒否・未完了は利用量が分かれば精算して停止し、保存応答を詳細から確認・取得できます。自動修復の追加課金は行いません。
実行プロセスが終了しただけなら、復旧確認後に「停止後の続きを実行」で同じ依頼の残りを再開します。上限回数・費用枠はリセットしません。

正式採用の保存途中は、他の保存をせず「正式採用の保存を再開」を押します。
全対象ファイルを先に照合し、既存履歴を保った追記だけを許可します。後から別の編集があれば自動復旧を停止し、差分とバックアップの確認を求めます。
応答履歴があるのにstory_ai.jsonが欠損した場合も、0から初期化してAPIを再送せず停止します。
全ワーカーで同じMANGA_BUDGET_DBを使用します。生成後にDBのパスを替えて0円から始める操作は拒否します。
作品フォルダ全体と、別管理の予算DB・初期化記録を停止後にバックアップしてください。履歴は自動削除しません。

この専用候補履歴は既存GitHub作品同期へ自動追加しません。採用済み脚本と評価は従来の同期経路を維持します。候補・応答も残すには作品フォルダ全体をバックアップします。

## Macでの確認

Python 3.11・Streamlit 1.40.2・Intel Mac/macOS 12を想定し、追加pip依存はありません。実機での確認は未実施です。
マージ後は、アプリ停止とバックアップの後、リポジトリ直下で更新します。

```bash
cd /実際の保存場所/manga
git switch main
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

MANGA_DATA_DIRとMANGA_BUDGET_DBは更新前と同じ外部保存先を使います。ZIP更新では元フォルダを残し、保存データをコードと分けてください。
`requirements.txt`が見つからない場合は、`app.py`と同じディレクトリにいるか`pwd`と`ls`で確認します。

```bash
# 実ユーザーデータを使わず、まだ存在しない出力先を指定する。
python scripts/verify_story_ai.py --output /tmp/manga-story-ai-new-demo
```

# AIキャラクター制作・一貫性管理（Phase 2-C）

「キャラクター・作風 → AIキャラクター制作・一貫性管理」を追加しました。既存6工程、AI一括生成・採用、手動人物編集、基準画像アップロードは維持します。
**初回リリースは無料モック専用です。有料テキスト／画像APIには接続しません。** APIキー・追加pip依存は不要です。

## 操作手順

### 1. 正式脚本を確定する

AI企画・ストーリーや従来の取り込みで、脚本を正式なStoryStoreの新しい版として保存します。
「企画・ストーリー → 比較・脚本確定」で人間が確認・確定してください。AI候補のUUIDは使いません。
新画面の上部で対象の正式版を選びます。初期値は最新です。未確定の版では抽出・採用・バイブル保存・新規プロンプトを開始できません。
過去版の提案や履歴は閲覧できますが、過去版を再び制作対象にするには既存の履歴で復元し、最新正式版を再確定します。

### 2. 抽出・照合

「無料モックで人物候補・設定案を生成」を押します。明確な話者ラベル、登録人物名、利用者の追加指定名、`人物：名前`の表記を抽出します。
描写だけに現れる未登録人物は「追加して確認する人物名」へ1行1名で指定できます。脚本に根拠がなければ拒否します。
根拠のページ・コマ・原文、別名・敬称・Unicode NFKC・空白・名字／名前の部分一致による既存候補を記録します。
一致しても本人と断定しません。同名別人・代名詞・不明話者は確認待ちです。ナレーションは人物へ自動登録せず、音声工程の既存ナレーターIDを維持します。

モックは汎用の日本語理解モデルではありません。年齢・性別等を推測で埋めず、未指定情報は空欄にします。
`悠真が立っている。髪色：黒、服装：制服`のように、一人だけを対象とした明示ラベルは事実の候補として扱います。
複数人物が混在する文や異なる記述からは属性を勝手に割り当てません。新しい識別特徴は「AI提案」と明示したモック案です。

同じ元脚本・人物・追加名・別名の依頼は再利用します。「新しい人物提案を作る」を選ぶと旧案を保持して別の依頼を作ります。
人数0件は空の不正提案を作らず、その状態を保存します。候補上限50人、追加名50件、本文50万文字などの入力上限を設けています。

### 3. 候補確認・採用

人物候補を一人選び、反映先を「新規人物」または既存UUIDから**自分で選択**します。既存候補は自動選択しません。
現在値・提案値・根拠・区分を縦に比較し、採用する項目だけを選択します。選択項目は編集できます。
既存人物の更新では、初期選択を視覚的な差別化だけに絞っています。選択外の値を空欄で上書きしません。
同名・類似名候補と別人として新規登録する場合は、その確認も必要です。名前を維持した同名別人の更新は、選んだ既存UUIDだけを更新します。

同定・原文・事実と提案・選択項目を確認して「この人物の選択項目だけを正式採用」を押します。
新規UUIDの発行はこの操作時だけです。既存UUID、参照画像一覧、primary_reference_id、削除履歴、コマ候補・採用画像・選択履歴は保持します。
原案・編集・選択項目・同定承認と採用先を既存assistant.jsonへ保存します。採用後は閲覧専用になります。
Phase 2-Cの提案は、従来画面の一括採用で固定ロックを迂回できません。新画面で同定・部分採用を確認してください。

### 4. キャラクターバイブル

正式人物を選び、現在の設定と前のバイブルを比較します。年齢・髪型・髪色・瞳・体格・服装・特徴・身長・視覚的な差別化から、非空項目を固定してロックできます。
表情・姿勢・照明は場面で変わる要素として分けます。別名・呼称は利用者が確認して登録します。
衣装替え・回想・成長・季節変化は、対象ページ／コマ、変更項目、設定値、理由を指定した**場面例外**へ記録します。基本プロフィールは変えません。
同じコマへ矛盾する例外は保存できません。解除やロック変更も新しいバイブル版を保存し、旧版は残します。

基準画像IDと参照一覧を既存ArtworkStoreへリンクし、保存時にSHA-256も記録します。
未登録・欠損は未完了のままです。画像の自動生成・採用はしません。任意のチェックを入れたときだけ、選択した1枚の縮小画像と原画像ダウンロードを読み込みます。
最後に確認・採用根拠を記入して承認し、「確認済みバイブルを新しい版として保存」を押します。

ロックはこの画面の人物提案の採用を保護します。既存の手動人物編集は維持し、そこで変更した場合はバイブルと過去検査を古い状態として再確認します。
ファイル移動・コピー等による参照の更新も軽量表示では再確認対象になることがあります。実行時の検査とプロンプト作成ではハッシュを確認します。

### 5. 矛盾チェック

「静的一貫性チェックを実行」で保存済み設定を検査し、結果を履歴へ保存します。未実行を「問題なし」にはしません。

- 基準画像未登録・欠損・不正パス／リンク、未確認・古いバイブル。
- 同名・別名の混線、人物ID不明、話者と作画指示の対応、未設定・古い作画指示。
- `悠真：髪色=黒、服装=制服`のような作画指示の明示ラベル、または「コマごとの人物設定」の記録と、ロック・承認済み例外との矛盾。
- 同じページ内の設定変化、重要特徴が作画指示本文に明記されていない場合の補足案内。
- 古い脚本版のコマ設定、以前の人物・作画設定に基づく採用画像の再確認。

自然文の意味や実画像の顔・髪・衣装を解析した判定ではありません。画像ファイルがあるだけで外見一致を保証しません。
話者が画面外にいる場合など、指摘が意図した演出であることもあります。人間が根拠を確認します。
指摘から対象のコマ制作ワークスペースへ移動できます。そこから同じコマのバイブル付き統一プロンプトへ戻るボタンも追加しました。
脚本・人物・参照・作画指示・画像採用等が変わると過去の検査は古い状態になり、再実行を案内します。過去の指摘は削除しません。

### 6. 統一画像プロンプト

「画像プロンプト」で人物基準画像（正面／斜め／全身／表情差分）またはページ・コマを選びます。
バイブルと作画指示が古い場合、固定特徴・人物IDが矛盾する場合は、解消するまで新しいプロンプトを出しません。
未登録・欠損の参照画像は警告します。文字を描き込まない規則、作風・カラー設定、固定プロフィール、対象コマだけの例外、参照画像IDとハッシュを既存プロンプトへ補足します。
ページ編集の想定アスペクト比・トリミング時の余白も従来のプロンプト関数から引き継ぎます。

取得ボタンとコピーを全文より先に表示します。コピーできない環境ではテキストをダウンロードしてください。
**参照画像は利用者がChatGPTへ実際に手動添付する必要があります。** 画像本体は自動送信しません。
生成画像は従来の基準画像登録・コマ制作画面で手動登録・採用します。「制作履歴へ保存」はプロンプトだけを保存する操作です。

## 保存先・復旧・予算

| 保存先 | 内容 |
| --- | --- |
| 既存assistant.json | 人物提案・原案・根拠・モック依頼・編集・同定・部分採用。既存schema_version:1を維持 |
| 既存assistant_pending.json | 既存2ファイル採用トランザクション。Phase 2-Cでは人物・画像・他提案の保持条件も検証 |
| 既存artwork.json | 正式人物の正本。採用したフィールドだけ反映し、人物UUID・基準画像を維持 |
| character_ai.json | format:manga-character-ai / schema_version:1。バイブル、場面例外、コマ別指定、検査、保存プロンプト、イベントの追記履歴 |
| character_ai/initialized.json | 初期化済みの記録。メタデータ欠損時に0から始めないために保持 |

採用時は既存のロック順序とAssistantStoreのジャーナルを使い、提案・作画・評価・バイブルの版と最新確定脚本を確認します。
保存途中で失敗した場合は他の編集をせず、「人物採用の保存を再開」を押します。別編集がある場合は上書きを停止し、差分とバックアップを確認します。
初期化記録があるのにバイブルがない、採用記録があるのに提案履歴がない、画像・人物履歴があるのにartwork.jsonがない場合も停止します。JSONや記録を削除して回避しないでください。
単独バイブル保存も原子的です。保存後のエラーでは、再実行の前に画面を再読み込みし、実際の保存版を確認します。

履歴容量は16MiBを上限とし、自動削除・圧縮はしません。参照画像のハッシュ読込は1ファイル32MiBまでです。
作品フォルダ全体、外部の共通予算DBと初期化記録をバックアップしてください。
新しいcharacter_ai.json／ディレクトリは今回GitHub作品同期の自動対象に追加していません。既存の脚本・人物・画像・提案の同期形式は維持します。バイブルの持ち運びには作品フォルダ全体も保存します。

今回のモックは既存予算DBを作成・変更せず、残額0円や請求不明でも無料で動作します。実API送信0回・費用0円です。
有料人物生成アダプターは未実装です。環境にキーやMANGA_ENABLE_PAID_CHARACTERを設定しても送信しません。
モデル・料金・許諾・最大請求量の新規確認と個別承認を行っていないため、既存OpenAI接続へ無理に転送しません。
次の有料工程も同じ作品UUID・共通BudgetedExecutor／DBを使い、企画・音声等の消費を含む生涯500円／全作品月間5,000円を共有します。

## Macでの更新・動作確認

Python 3.11、Streamlit 1.40.2、Intel Mac/macOS 12を想定しています。追加依存はありません。Mac実機は未検証です。
アプリを停止し、作品フォルダと予算DBをバックアップします。リポジトリ直下（app.pyとrequirements.txtがある場所）で実行します。
未コミット変更がある場合は先に保全し、勝手な削除や上書きでブランチを切り替えないでください。

```bash
git status --short
git fetch origin feature/ai-character-consistency
git switch -c review-character-ai FETCH_HEAD
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

review-character-aiを既に作成している場合は、新規作成せずそのブランチを選択します。mainへのマージは行いません。
MANGA_DATA_DIRとMANGA_BUDGET_DBは今までと同じ保存先を使います。ZIP更新ではコードとデータを分け、元フォルダを残してください。

実ユーザーデータを使わず確認するには、**まだ存在しない専用フォルダ**を指定します。

```bash
python scripts/verify_character_ai.py --output /tmp/manga-character-new-demo
# 自動テストは開発依存を入れてから実行
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

スクリプトは3人物＋ナレーター・8ページ24コマ、既存人物1人の部分更新と新規2人、バイブル3件、矛盾検出→解除→再検査、5プロンプトを検証します。
report.jsonに実測件数・元ファイルの前後SHA・外部API送信0・費用0円を記録します。色面の小画像は検証素材で、AI生成の外見品質を示しません。
旧設定に基づく採用画像は保持して再確認事項を残すため、矛盾解消後も静的指摘が0件とは限りません。同じ出力先の再実行は全ファイルを変更せず拒否します。

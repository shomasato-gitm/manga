# Phase 2-D2：単発画像APIの準備と安全性

## 現在の対応範囲

Gemini Developer API用の単発RESTアダプターを用意した。ただし**実ネットワーク送信は無効**。
公式の最大総課金量・モデル別対応・利用条件を確認できないため、fake HTTPでのみ検証した。
Google AI Studio/ChatGPTの月額料金はAPI無料枠として扱わない。
調査日は2026-10-24。[一次資料・単価・未確認項目](IMAGE_API_LIVE_COMPARISON.md)を参照。

有料APIの実呼び出し、人物一貫性の実画質、Intel Mac実機の検証は行っていない。
無料モック・手動画像・既存の制作、GitHub同期、音声・動画機能を維持する。

## Macでの更新と画面操作

更新前にアプリ・生成処理を終了し、作品フォルダ全体と共有予算台帳（`.initialized`を含む）を別々にバックアップする。
レビュー時はPRの作業ブランチを取得する。未コミット変更がある場合は先に内容を保存する。

```bash
cd /実際に保存した場所/manga
git fetch origin
git switch feature/ai-image-live
git pull --ff-only origin feature/ai-image-live
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Python 3.11/3.12、Streamlit 1.40.2、Pillow 10.4.0。追加SDK・npm・モデルのダウンロードは不要。
仮想環境がない場合はREADMEの初回起動手順で作成する。

1. 作品を開き、脚本を確定する。人物バイブル・必要な基準画像・作画指示を確認する。
2. **イラスト制作 → AI画像生成・採用 → 生成計画**で1対象の計画を作る。
3. **生成・手動取り込み**は従来どおり無料モックが初期値。
   実APIを選ぶと、対象の脚本版・参照ID/SHA・個々の送信同意・料金カードの入口を表示する。
4. **共有予算の支出・予約・残額を確認**で必要時のみ計測。請求不明は予約に含み、
   作品生涯500円／全作品月間5,000円から差し引く。残額を見た時点では予約しない。
5. 本番の費用検証・依頼保存・**この1枚を生成**は現在無効。
   将来解除後も、最大費用検証→個別同意・依頼保存→依頼IDごとの二段階目承認が必要。
6. 成功した候補は**候補比較・採用**で目視・権利確認を保存し、別操作で正式採用する。
   作成だけではArtwork・人物・既存画像・採用状態を変えない。

キーは環境変数 `GEMINI_API_KEY`、機能フラグは `MANGA_ENABLE_IMAGE_API` の設計。
**今は設定不要で、設定してもno-goは解除されない。** JSON・ソース・ログ・PRへキーを記載しない。
独自のAPI URLを指定する機能はない。参照画像の外部送信は、全参照の個別同意がそろうまで拒否する。

## 無料の一連検証

```bash
source .venv/bin/activate
python scripts/verify_image_ai_live_fake.py --output "$HOME/MangaLiveFake-20261024-01"
```

指定先は**存在しないフォルダ**に限る。元の `MANGA_DATA_DIR` / `MANGA_BUDGET_DB` を使用せず、
指定先の新規fixtureと専用の共通台帳へ一時的に切り替える。既存ユーザーデータを読み書きしない。
ソケット接続を遮断し、fake HTTPの1回だけを実行する。既存フォルダ・リンクは拒否する。

架空の単価・上限で最大予約14.300000円、usage換算5.922400円を同じBudgetedExecutorで計算する。
**架空の記帳で、実際のAPI費用は0円**。本番価格カードとして使用しない。
未採用状態を確認後、テストコード内の明示承認によってレビューと採用を検証する。
スクリプトが人物画像を目視評価したことにはならない。テスト画像にはTEST ONLYを付ける。

## 保存形式と復旧

既存 `image_ai.json` のschema_version=1とルート構造を維持し、ジョブに `live` を追加する。
旧mock/manualジョブは従来どおり読める。旧ファイルを自動変換しない。

- `live`：モデル、料金カード全体・SHA、公式URL・確認日、入力/出力/思考の最大量、1K正方形1枚、
  品質はprovider-default固定（品質パラメーターの自動追加・昇格なし）、自動再試行0回、
  FX・税・安全係数、最大予約額、参照同意ID、本文SHA、承認ハッシュ、共有台帳の絶対パス、fake区別。
- ジョブ：request_id、実行回数、状態、応答ID、応答SHA、返却モデル、usage、換算精算額、固定されたエラー分類。
- `image_ai/jobs/<request_id>/live_response.json`：依頼ID・入力SHAに結び付けた応答封筒。
  ヘッダー、例外全文、任意の診断を保存しない。未知のusageは請求不明として止める。
- 候補：従来の不変 `image_ai/candidates/<UUID>.png`。PNG検証・正規化後に保存し、
  同じIDに異なるバイト列を上書きしない。fakeは `mock: true` を維持する。

状態は `queued → reserved → sending → response_saved → settled → ready`。
予算の予約・実行権は共有SQLite台帳が正であり、画面の状態だけで送信済みかを判断しない。
全プロバイダーの `BudgetedExecutor.run` 内の実行コンテキストに加え、
本番能力確認とフラグを通過しない限り、アダプターの直接呼び出しも拒否する。

送信ロックは別の非待機flockで保持し、長い通信中は全プロジェクト編集ロックを占有しない。
送信直前に版・入力SHA・参照・料金期限・台帳を再検証する。進行中に元データが変わった場合は
候補を保全するが、既存のReview/Adoptが古い候補の採用を拒否する。

| 状況 | 操作 |
| --- | --- |
| 予算不足・料金期限切れ・参照/版の変更 | 未送信で停止。条件を確認し再計画する |
| タイムアウト・429/5xx・応答保存失敗・usage不明 | `uncertain`。予約を保持。手動でも同じIDを再送しない |
| 有効なusageだが画像0/複数・拒否・破損・サイズ不一致 | 利用量は精算し候補化を停止。無料失敗と見なさない |
| 精算後のPNG/メタデータ保存失敗 | `artifact_pending`。履歴から同じ依頼の**保存だけ**を復旧 |
| 応答保存後、精算前の中断 | 予算画面でプロバイダー明細を手動照合。その後、同じ応答・精算が一致すれば保存復旧 |
| 応答自体の欠損・不明usage・異なる精算 | 保存復旧も停止。バックアップ・明細を確認する。自動再送・無料モック置換・予約解除はしない |
| 利用量の上限違反 | 精算値と指摘を保持し、新規画像依頼を停止。料金根拠の再レビューが必要 |

`cost_jpy` は凍結した最高モダリティ単価とusage、為替、税の**保守的な換算額**。
外部請求書との完全一致を保証しない。精算時は予約用の安全係数を重ねず、
有効usageの実額が予約を超えれば共有台帳に記録し、既存の超過停止・手動照合を使う。
モデル別のusage内訳や新しい課金項目が未確認なら自動精算しない。

## 音声・動画・次の実試験

正式採用後は既存ArtworkStoreのPNG・採用IDを使用する。人物UUIDや音声/動画JSON契約は変更しない。
fake画像は既存のTEST_ONLYマーカーで、音声タイムライン/動画素材確認でも警告する。
24コマへの受け渡しと既存FFmpeg実動画テストを回帰テストで確認する。

実送信解除には比較資料に記載した最大課金量、参照、モデル別プロトコル、商用・データ・SynthID条件の
一次資料確認とレビュー付きPR、プロバイダー側の支出制限、専用環境の設定が必要。
その後も、**少額1枚の有料API実呼び出しへの別途明示承認**を受けるまで送信しない。
顔一致・衣装・人体・見切れ・透かし・権利・公開可否は実画像で人間が確認する。

# ChatGPTプロジェクト運用ガイド（AI漫画スタジオ）

## 目的
ChatGPTプロジェクトを作品制作・レビューの入口にし、GitHubの `manga` リポジトリをバージョン管理された成果物の保存先にする。既存Streamlitアプリはページ合成・PDF/PNG/ZIP出力とローカルの詳細編集に使い続ける。

## 現在の制約
- 現在のアプリはChatGPTへの入力・JSON返却・画像の受け渡しが手動。OpenAI APIは未利用。
- `data/projects/*` は `.gitignore` の対象。アプリ保存だけでGitHubに作品データは反映されない。
- GitHubへコミットする際は、必要なJSON等を明示的にステージ・保存する。ローカルの画像や出力は、自動同期しない。
- ChatGPTプロジェクトの指示を設定しても、Streamlitのローカル実行や画像ファイルの自動アップロードは行われない。

## 推奨チャット
- 00｜総合管理：方針、進捗、改善計画
- 01｜漫画制作スタジオ：企画、脚本、推敲、作画指示、制作進行
- 02｜キャラクター・作画：設定と参照画像、コマ画像の確認
- 03｜システム開発：Codexでの機能改善と検証
長編作品は必要に応じて作品専用プロジェクトで扱う。

## ChatGPTプロジェクト「指示」に貼る文章
あなたはAI漫画スタジオの制作統括です。
- 最初に作品名・現在の工程・確認できる最新の確定資料を把握する。
- 作品設定、ストーリー、キャラクター外見、ページ・コマ番号の一貫性を優先する。
- ストーリーJSONは既存形式（schema_version, title, summary, pages、各pageのpage, summary, panels、各panelのpanel, description, dialogue, narration）を維持する。
- 脚本の生成→編集評価→必要な修正→作画指示→画像生成・レビュー→合成・出力の順に進める。評価・改善はできる範囲で繰り返す。
- 確認済みの版と未確定の案を区別する。古い版を自動的に最新として扱わない。
- GitHubへの読み書きは実際に接続されている機能だけを利用し、保存や更新を実行していない場合は「保存済み」と言わない。
- 既存データを上書きする前に対象ファイルと変更内容を照合する。脚本・画像の採用や確定はユーザーの方針に従う。
- ローカルStreamlitアプリにしかない編集・合成・出力機能は、チャット内で実行できるとは断定しない。
- API従量課金を前提とした仕組みは、ユーザーの了承なく提案・実行しない。

## おすすめの実行用チャット最初のメッセージ
「AI漫画スタジオを開始。GitHubのmangaリポジトリと、必要に応じて指定した作品資料を確認して、現在の工程・次の作業・未確定事項を教えて。ストーリー制作を始める場合、保存済みのJSON形式を守って進めて。」

## 導入順
1. ChatGPTにAI漫画スタジオ用プロジェクトを作り、上記指示を登録する（プロジェクトUIで操作）。
2. 推奨チャットを作成し、実行用チャットを制作の入口にする。
3. 作品JSONの取得・評価・改善・GitHub保存を1作品で試す。
4. 画像生成と参照画像の運用を確立する。
5. 既存アプリへの成果物の読み戻し、漫画の合成、出力を試す。
6. 手作業が残る箇所のみ、Codexで取り込み・出力の改善を検討する。

## 保存方針
- ソースコード：GitHubの `manga` リポジトリ。
- 確定した作品JSON：GitHubに管理対象パスを新たに設けて明示的にコミットする（例 `works/<作品ID>/story.json`）。これは将来の運用案であり、現時点でアプリの自動保存先ではない。
- 参照画像・生成画像・大容量の完成出力：容量制限やGitHubへの適性を確認し、Git LFSや別ストレージも含めて保存先を決める。既存のローカルファイルを無断移行しない。


## GitHub半自動連携の追加

アプリの「完成・書き出し → GitHub作品同期」から、作品の取得・候補検証・明示採用・作品ブランチへの保存を行えます。
従来の手動ファイル取り込みも維持しています。ChatGPT側のGitHub書き込みは、実際に接続された機能・権限がある場合だけ利用してください。
取得済みというだけで正式採用・評価済み・完成とは扱いません。APIやChatGPTの自動呼び出しはありません。
詳細は [GitHub半自動連携の操作ガイド](github-studio-sync.md) を参照してください。

公式比較を実装前に再取得し、厳格な画像編集の請求上限を確認できないため2-D2は送信不可とします。2-D1はモック・手動取り込みで全操作を検証します。

| 再利用する正本・処理 | 新規の責務 |
| --- | --- |
| CharacterAIService.prompt、人物UUID、確定済みStoryStore版、バイブルの版・参照SHA・場面例外 | 画像生成計画・対象に関係する入力だけの更新検知。別コマの画像採用で全候補を古くしない |
| prepare_image、ArtworkStore.add_reference / select_reference / add_panel_image / select_panel_image | 候補はimage_ai/へ分離。人間の品質・権利確認後に限り既存メソッドで正規登録・選択。新規登録IDを再発行して復旧しない |
| 既存の画像フォルダ・選択履歴・基準画像、共通UIランタイム・サムネイルキャッシュ | ジョブ・候補・同一依頼の再利用・再生成・レビュー・採用ジャーナル・保存再開を独立image_ai.jsonへ保存 |

| 音声タイムライン／video_sources | 正規の採用画像ID・PNG・SHAで連携。テスト画像は明示表示し、本物のAI生成・完成品質と区別 |

新規ファイルはimage_ai_models/storage/planning/service/jobs/adoption/provider/価格情報UI等を責務別に分割します。既存スキーマは変更しません。
プロジェクト→ストーリー→image_aiロック→既存ArtworkStoreメソッドの順で協調し、外側でartworkロックを再取得してデッドロックしない設計にします。参照登録でバイブルが古くなった場合は人間が再確認します。
採用前に一意な採用IDを記録し、ArtworkStoreのoriginal_nameに対応印を付けます。保存中断後も同じ登録を検出し、二重登録・二重の選択履歴を作りません。既にメタデータが保存された画像のファイル欠損は、既存IDを保持する専用のArtworkStore復旧処理で保全します。
元画像・候補・レビュー・履歴を自動削除せず、競合やハッシュ不一致時は停止します。手動画像の元バイト列もジョブ内に保持し、変換したPNGと区別します。静的検査は画像内容の一致を保証しません。

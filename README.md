# AI漫画スタジオ（AI制作アシスタント対応）

漫画の企画を保存し、**ユーザーがChatGPTと手動で受け渡しして**ストーリーを制作するStreamlitアプリです。
プロジェクト作成に加え、プロンプト生成、ストーリーJSONの取り込み、ページ単位の編集、履歴の保存・復元ができます。
第3段階ではキャラクター設定・参照画像、コマ別の作画指示、画像生成用プロンプト、候補画像の登録・採用を管理します。
さらに、参考作品の分析、版に紐づくAI評価、選択した範囲の改善、実際のJSON差分比較、脚本の採用・確定に対応しています。
第4段階では、採用画像のページ自動配置、コマ割り編集、日本語の吹き出し、PNG・PDF・縦読みSNS出力ができます。
第5段階では、キャラクター・参考作品・全コマの作画指示をAIへまとめて提案させ、JSONを確認・編集・選択採用できます。作画の評価・改善、画像プロンプトの一括出力にも対応します。

**OpenAI API・非公式API・ChatGPTのWeb画面の自動操作は一切使用しません。APIキーは不要です。**
アプリからAIサービスへの通信は行わず、APIによる追加課金は発生しません。
ChatGPTへの貼り付けと返答のコピーはユーザーがご自身のWeb画面で行います。ChatGPT側の利用制限は契約プランに従います。
画像生成はユーザーがChatGPTで行います。アプリは生成された画像をローカル保存し、採用画像から漫画ページを合成します。

## Intel Macでの準備

推奨環境は **Intel Mac・macOS 10.15〜12・Python 3.11** です。
主要な依存パッケージを、古いIntel Mac向けのバイナリ配布があるバージョンに固定しています。
Python 3.9〜3.12に対応する構成ですが、まずは3.11を利用してください。
macOS 10.14以前はPyArrowの配布対象外のため、この構成では対応しません。
Mac実機での動作確認は未実施です。

1. Pythonがなければ [Python公式のmacOSダウンロード](https://www.python.org/downloads/macos/) から、macOSの対応条件を確認してPython 3.11をインストールします。OS付属のPythonは変更しません。
2. ターミナルを開き、ダウンロードまたはcloneした `manga` フォルダに移動します。
3. 以下を1行ずつ実行します。`.venv` は、このアプリ専用のPython環境です。

```bash
cd /path/to/manga
python3.11 --version
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

`/path/to/manga` は実際のフォルダのパスに置き換えてください。
ブラウザが自動で開かなければ、ターミナルに表示されるLocal URLをブラウザで開きます。
終了するにはターミナルで `Control + C` を押します。
次回からはフォルダに移動し、`source .venv/bin/activate` と起動コマンドだけで起動できます。

すでに利用している場合は、アプリを終了してデータフォルダをバックアップした後、
次の手順でコードを更新して再起動してください。依存パッケージも同期します。第5段階の追加パッケージはなく、既存JSONの移行操作も不要です。

```bash
cd /path/to/manga
git status --short
git pull --ff-only
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

`git pull --ff-only` がローカルの変更などで失敗した場合、強制リセットをせず、変更を保存してから対応してください。

Pythonのコマンドが見つからない場合はインストール後にターミナルを開き直し、`python3.11 --version` を確認してください。
証明書エラーが出る場合、python.orgのインストーラーに付属する `Install Certificates.command` を実行します。証明書検証を無効にする必要はありません。
別のアプリがポートを使用している場合は、起動コマンドの末尾に `--server.port 8502` を追加できます。

## プロジェクトの作成・再読み込み（既存機能）

1. タイトル・ジャンル・あらすじを入力します。ページ数は初期値8、指定範囲は1〜100です。
2. 「プロジェクトを保存」でJSONファイルが作成されます。
3. 左側の一覧から選び、「選択したプロジェクトを開く」で再読み込みします。
4. 読み込んだ内容を変更して保存すると、同じプロジェクトを更新します。
5. 「新規プロジェクト」でフォームを空にすると、別のプロジェクトを作成できます。同じタイトルでも別々のIDで管理します。

一覧の「開く」や「新規プロジェクト」は未保存の入力を置き換えます。必要な内容は先に保存してください。
JSONのダウンロードは最後に保存した内容が対象です。フォームの未保存内容は含みません。
この版は個人がローカルで使う想定です。同じプロジェクトを複数の画面で同時に編集すると、最後の保存が反映されます。

## ChatGPTとストーリーを作る手順

1. プロジェクトを作成・保存するか、一覧から開きます。通常は8ページにします。
2. 下部の「ChatGPT用プロンプト」を開きます。保存済みの設定から、全ページ・各ページ3コマを想定したプロンプトが自動で作られます。
3. プロンプト枠の右上にある**コピーボタン（重なった四角。マウスを重ねると表示）**を押します。Streamlit標準のコピー機能です。必要なら枠内を選択して手動コピーもできます。
4. ご自身でChatGPTを開き、新しい会話に貼り付けて送信します。
5. 返されたJSONをコピーし、アプリの「JSON取り込み」→「貼り付け」に貼り付けます。またはUTF-8の `.json` ファイルに保存し、「JSONファイル」から選びます。
6. 「検証してストーリーを保存」を押します。形式やページ数が不正なら、問題の場所を表示し、既存ストーリーは変更しません。成功すると新しいバージョンとして保存します。
7. 「ページ編集」でページを選び、概要、各コマの描写・セリフ・ナレーションを編集します。「このページを保存」で、他のページを保ったままストーリー全体を履歴保存します。タイトルと全体のあらすじも編集できます。
8. 評価・改善したい場合は「AI評価・改善」で対象版を選び、評価JSONを取り込みます。その評価から改善用プロンプトを作成し、改善版JSONを新しい履歴として保存します。詳しくは次の節を参照してください。
9. 元に戻す場合は「バージョン履歴」で過去版を選び、内容を確認して「このバージョンを復元」を押します。復元も新しい版として保存するため、それまでの履歴は消えません。

プロンプト・JSONのダウンロードは**最後に保存した内容**が対象です。
ページやプロジェクトの切り替え、新しい取り込み、履歴の復元の前に、編集中の内容を保存してください。
フォームの未保存内容は引き継がれません。
企画のページ数を変更しても既存ストーリーは自動で増減しません。画面に差異を表示し、次の取り込みでは新しい設定ページ数を検証します。

### ChatGPTなしで取り込みを試す

8ページのプロジェクトを保存して、[examples/story_8pages.json](examples/story_8pages.json) を取り込むと、24コマのサンプルを編集できます。
自分でJSONを作る場合は、画面の「JSONひな形をダウンロード」も利用できます。ひな形の記入用の文は実際の内容に置き換えてください。

### 受け渡すストーリーJSON

| 項目 | 形式・内容 |
| --- | --- |
| `schema_version` | 1。省略時も1として扱う |
| `title` | タイトル（100文字以内）。省略時はプロジェクトのタイトル |
| `summary` | 全体のあらすじ（4000文字以内）。省略可 |
| `pages` | 設定したページ数の配列。通常8ページ、1から順に並べる |
| `pages[].page` | 1からのページ番号 |
| `pages[].summary` | ページ概要（2000文字以内）。省略可 |
| `pages[].panels` | コマの配列。目安3コマ、1〜6コマを許可。3以外は警告を表示 |
| `panels[].panel` | 各ページ内で1からのコマ番号 |
| `panels[].description` | 必須の描写（4000文字以内） |
| `panels[].dialogue` | 話者を含むセリフの文字列（4000文字以内）。省略可 |
| `panels[].narration` | ナレーション（2000文字以内）。省略可 |

多少の出力の揺れは、取り込み時に次のように正規化します。

- JSONの前にUTF-8 BOMがあっても読み込みます。説明文の中に1つだけある ` ```json ` コードブロックも読み込めます。
- `{"story": {...}}` や `{"ストーリー": {...}}` の外側のオブジェクトを許可します。
- `タイトル`、`あらすじ`、`ページ`、`ページ番号`、`概要`、`コマ`、`コマ番号`、`描写`、`セリフ`、`ナレーション` などの日本語キーを許可します。
- `page_number` / `panel_number`、描写の `scene`、セリフの `dialogues` にも対応します。
- ページ・コマ番号が省略されていれば配列順から補います。`"1"` などの数字文字列も整数に変換します。
- セリフは文字列の配列、または `{"speaker": "話者", "text": "セリフ"}` の配列でも取り込めます。話者の `character` / `話者`、本文の `セリフ` も使えます。改行区切りの文字列として保存します。
- 任意の本文項目の省略・`null` は空文字列にします。未知の項目は保存せず、項目名を警告します。必要な情報なら対応項目に移してください。

番号の重複・欠番、ページ数の不一致、空の描写、同じ意味の項目の矛盾、未対応のバージョンはエラーです。
複数のコードブロックは1つに絞ってください。JSONは1MB以下・UTF-8形式とし、全角引用符、コメント、末尾の余分なカンマは修正してください。

## 参考作品の分析・評価・ブラッシュアップ

制作状況を「参考作品登録 → 参考作品分析 → ストーリー作成 → AI評価 → AI改善 → 再評価 → 脚本確定」の順に表示します。
状態は保存済みの記録から計算し、未実施のAI処理を完了と表示しません。参考作品の登録・分析は任意です。

### 1. 参考作品を管理する

「参考作品管理」で作品名、媒体（漫画・小説・映画・アニメなど）、ジャンル、参考にしたい理由、
好きなシーン・演出の概要、参考にしたい技法、参考にしたくない要素、出典URL、メモを登録します。
作品名と媒体は必須です。各項目は2000文字以内とし、著作物の本文や固有のセリフの大量コピーではなく、ご自身の短い要約・観察を記入してください。

一覧から選んで編集できます。削除時は確認チェックを入れます。削除は一覧から外す方式で、分析履歴は保持します。
URLは出典のメモとして保存するだけで、外部サイトの閲覧・取得・スクレイピングは行いません。

### 2. 分析プロンプトと分析JSON

1. 「参考作品分析」で対象作品を選び、プロンプト枠の右上からコピーしてChatGPTへ渡します。
2. 導入、主人公の目的・欲求、キャラクターの魅力、感情、伏線と回収、意外性、セリフ・沈黙・視覚的演出、クライマックス、結末の余韻の9項目を分析します。
3. ChatGPTの分析JSONを貼り付けるかUTF-8ファイルで取り込み、「分析JSONを検証して保存」を押します。
4. 「分析メモの履歴」で過去の結果も確認できます。

登録情報は確認済みの作品本文とはみなさず、情報不足や未確認の場面は「不明」とするプロンプトです。
分析には根拠と確認状態を記録します。アプリは作品内容を検証していないため、ユーザーも結果を確認してください。
登録内容を編集すると版番号が変わります。編集前の分析を新しい内容の結果として取り込もうとした場合はエラーになります。

分析JSONはプロンプトに含まれるひな形を使います。

| 項目 | 内容 |
| --- | --- |
| `schema_version` | 1 |
| `reference_id`, `reference_version` | プロンプトに記載された作品ID・登録内容の版番号。そのまま返す |
| `aspects` | `opening`, `goal`, `characters`, `emotion`, `foreshadowing`, `surprise`, `expression`, `climax`, `ending` の9項目 |
| 各項目の `analysis` | 分析文。不足情報は不明と明記 |
| `abstract_technique` | 他作品の固有の表現を再現しない、抽象的な技法 |
| `basis`, `status` | 根拠と「ユーザー要約に基づく」「未確認」「不明」のいずれか |
| `unknowns` | 不明点・追加で必要な情報 |

### 3. 技法を参考にオリジナル脚本を作る

「ChatGPT用プロンプト」で参考作品を0〜3作品選べます。参考なしでも従来どおり生成できます。
登録した抽象的な技法と、現在の登録内容に対応する分析のうち「ユーザー要約に基づく」技法を組み合わせます。
古い版の分析や、シーン概要そのものはストーリー生成プロンプトへ渡しません。

プロンプトはオリジナルの人物・世界観・設定を使い、既存作品の固有の展開・場面・セリフを再現しないよう指示します。
登録済みのキャラクター設定も含めます。標準は8ページ・各ページ約3コマで、ページ数は企画の設定を使います。
生成結果は既存のストーリーJSONとして「JSON取り込み」から保存します。

### 4. ストーリーを評価する

1. 「AI評価・改善」で評価対象の版を選びます。初稿や過去版も評価できます。
2. 評価プロンプトをChatGPTへ手動で渡し、**評価用JSON**を受け取ります。
3. 「評価JSONを検証して保存」を押します。評価は選んだ版に紐づき、ストーリー自体は変更しません。
4. 同じ版を何度も評価できます。「使用する評価履歴」で過去の評価も確認できます。

評価項目は、導入の魅力、キャラクターの魅力、ストーリー構成、感情の盛り上がり、セリフの自然さ、伏線・回収、結末の余韻、オリジナリティの8項目です。
各0〜10点で、総合点は **8項目の合計 ÷ 80 × 100** を小数第2位までアプリが計算します。AIが別の総合点を返しても採用しません。
採点はAIの主観であり、客観的な品質や改善効果を保証しません。この注意を画面にも表示します。

| 評価JSONの項目 | 内容 |
| --- | --- |
| `schema_version` | 1 |
| `story_version_id` | プロンプトに記載されたストーリー版ID。そのまま返す |
| `criteria` | `opening`, `characters`, `structure`, `emotion`, `dialogue`, `foreshadowing`, `ending`, `originality` の8項目 |
| 各項目の `score` | 0〜10の数値。数値文字列も許可。NaN・無限大・範囲外は不可 |
| `good_points`, `problems`, `reason`, `suggestion` | 良い点、問題点、改善理由、具体的な改善案。不要な場合も「なし」等を記入 |
| `targets` | `[{"page": 1, "panel": 2}]` のような実在する対象。ページ全体は `panel:null`、全体の指摘は `[]` |
| `summary` | 総評 |

評価・分析JSONも1MB以下・UTF-8で、BOM、1つのJSONコードブロック、日本語キーに対応します。
不正な形式、対象版IDの不一致、存在しないページ・コマ、点数の不足・不正はエラーになり、既存データを変更しません。
ストーリーJSONは従来の取り込みへ、評価JSONは評価の取り込みへ戻してください。

### 5. 改善して、もう一度評価する

評価履歴を選び、改善したい項目と以下の方式を選択します。

- **全体を改善する**：選んだ項目の指摘を踏まえ、脚本全体を改善する。
- **特定のページ・コマだけを改善する**：対象を1件以上選び、その範囲だけを変更する。
- **特定の評価項目だけを重点的に改善する**：選んだ評価項目に集中し、無関係な改変を避ける。

追加の改善希望と「今回の改善理由・メモ」を確認し、改善プロンプトをコピーしてChatGPTへ渡します。
元のテーマ・世界観・人物設定・外見を維持する指示を含めますが、意味や表現の適切さはユーザーが結果を確認してください。

改善結果も**全ページを含む従来のストーリーJSON**です。「改善版を検証して新しい版に保存」から取り込むと、
改善元の版、使用した評価、方式、対象、理由を新しい履歴に記録します。元の版や評価は削除しません。
改善版のページ数は改善元に合わせます。企画側のページ数を変更している場合も、改善対象の版のページ数を維持します。
部分改善では、指定外のページ・コマ、タイトル、全体のあらすじが変わっていたら、実際のJSON差分で検出して保存を拒否します。
ページだけを指定するとそのページ内を変更できます。コマだけを指定した場合、ページ概要なども変更できません。

改善後は自動で新しい版が評価対象になります。新しい評価プロンプトをChatGPTへ渡し、返答の評価JSONを保存してください。
何度でも手動で改善・再評価を繰り返せます。通常の「JSON取り込み」でも改善版は保存できますが、改善元・理由との対応は自動では記録されません。

### 6. 比較・採用・脚本確定

「比較・脚本確定」で初稿・修正版・再修正版の点数と改善理由を確認し、比較する2版を選択します。
各評価項目の点差、変更されたページ・コマ、変更前後の描写・セリフ・ナレーション・概要を表示します。
差分はAIの説明から推測せず、JSONの値を直接比較します。ページ・コマの追加・削除も表示します。

各版の評価が複数ある場合は最新を比較します。未評価の版は空欄で、点数を推測しません。
過去版の採用は同じ内容を新しい最新履歴として保存します。同一JSONの採用元版に評価があればその旨を明記して表示し、再評価扱いにはしません。
「今回の改善理由」は保存時に記録した理由であり、実際の差分とは分けて表示します。

採用したい版を選んで「この版を脚本として採用」を押し、内容を確認して「現在の脚本を確定」を押します。
確定はユーザー判断で行えます。確定後に脚本の内容が変わると、既存画像や作画指示との不整合に注意する通知を表示します。
画像・作画指示は自動で書き換えません。各コマを見直し、必要なら再作画して再度確定してください。

## キャラクター・コマ画像を作る手順（第3段階）

プロジェクトを開くと、下部に「キャラクター・作画・画像管理」が表示されます。
作画指示とコマ画像の登録には、第2段階で保存したストーリーが必要です。キャラクターはストーリー取り込み前にも登録できます。

### 1. 作風とキャラクターを登録する

1. 「プロジェクトの作風」に、白黒／カラー、線画、塗り、雰囲気などを入力して「作風を保存」を押します。作風はこのプロジェクトの各プロンプトに共通で反映します。
2. 「キャラクター設定」→「新規キャラクター」で名前・年齢・性別・髪型・髪色・目の色・体格・服装・性格・特徴を入力し、「キャラクターを保存」を押します。名前のみ必須です。年齢は「17歳」「不明」などの文字列で入力できます。
3. 別の人物を追加するときは再び「新規キャラクター」を選びます。既存の人物を選択して保存すると、その人物を更新します。同名の人物も別々に管理できます。
4. 削除する場合は「キャラクターを削除」を開き、対象名を確認してチェックを入れ、「このキャラクターを削除」を押します。

削除は一覧から非表示にする方式です。参照画像・候補画像・登録時の人物設定を残すため、ディスク上の画像は削除しません。
削除した人物を使っている作画指示は警告となるため、登場キャラクターを選び直して保存してください。

### 2. キャラクターの基準画像を作る

1. 保存した人物を選び、「生成する向き・種類」を正面・斜め・全身・表情差分から選び、表情を指定します。
2. 表示された日本語プロンプトを右上のコピーボタンでコピーし、ご自身でChatGPTへ貼り付けて画像を生成します。
3. ChatGPTで画像をダウンロードし、アプリの「キャラクターの参照画像」から選びます。種類とメモを入力して「参照画像を保存」を押します。
4. 正面・斜め・全身・表情差分などを繰り返し登録できます。最初の画像を基準画像とし、「基準にする参照画像」→「基準画像を選択」で変更できます。
5. 別の画像を生成するときは、参照画像をアプリからダウンロードし、ChatGPTへ**手動で添付**してください。プロンプト内のファイル名はアプリからダウンロードしたPNGの名前と一致します。

プロンプトをコピーしただけでは画像は送信されません。基準画像や補助画像も同じChatGPTの会話に添付してください。
同じ外見を保つための指示は含めますが、実際に生成された顔立ち・服装などはユーザーが目で確認します。

### 3. コマごとの作画指示とプロンプトを作る

1. 「コマの作画指示」でページ・コマを選びます。保存済みストーリーの描写・セリフ・ナレーションが表示されます。
2. 登場キャラクターを選び、場所・時間帯・表情・ポーズ・カメラ角度・構図を設定します。複数人の場合は「ルナ：笑顔、ソラ：驚き」のように表情を指定できます。
3. 「このコマの作画指示を保存」を押します。指示はストーリーJSONを変更せず、別に保存します。
4. 作風・キャラクター設定・作画指示・ストーリーを組み合わせた日本語プロンプトが表示されます。コピーして、人物の参照画像と一緒にChatGPTへ渡してください。

プロンプトは外見の統一を指示し、**セリフ・吹き出し・文字・ナレーションを画像に描き込まない**方針です。
セリフは場面の意味を伝える参考情報として渡します。登場キャラクターを選ばない場合は、人物を追加しない背景中心の指示になります。
未保存の設定はプロンプトに反映しません。画面やコマの切り替え前に保存してください。

### 4. コマ画像を登録・採用する

1. 「生成画像・採用一覧」で対象のページ・コマを選び、ChatGPTからダウンロードした画像を選択します。
2. 「候補画像を保存」で登録します。同じコマに複数の候補を追加できます。同じファイル名でも上書きしません。
3. 候補を見比べ、「採用候補を選ぶ」→「選んだ候補を採用」を押します。新規登録だけでは採用になりません。
4. 下部の「○ページの採用画像一覧」で、各コマの採用状況を確認します。未採用のコマも表示します。ページの合成・出力は下部の「漫画ページ編集・出力」で行います。

採用を変更しても過去の候補は削除しません。候補ごとの「登録時の作画条件」で、その時の描写・作風・人物・作画指示を確認できます。
この記録は登録時点のアプリの設定で、ChatGPTで実際に使ったプロンプトを自動取得するものではありません。

ストーリーのコマ内容を変更すると、以前の作画指示・画像に警告が付きます。指示を確認して保存し直すと、現在の内容に結び直せます。
以前の画像を採用する場合は、警告を確認して選んでください。
コマ数・ページ数を減らしても画像は残り、「現在のストーリーにないコマの画像履歴」から確認できます。
作風やキャラクターの変更後も画像は自動再生成しません。必要に応じて新しい候補を追加します。

### 取り込める画像

- PNG・JPEG・WebPの静止画。1ファイル20MB・2400万画素以下です。アニメーションやHEICは取り込めません。
- 拡張子だけでなくPillowで画像の内容を検証し、向きの情報を反映したPNGとして保存します。
- 透過画像は透過を維持し、EXIFや画像内コメントなどのメタデータは保存時に除きます。元のダウンロード画像そのものは変更しません。
- 変換後に20MBを超える画像もエラーになります。その場合は元の画像を小さくして再登録してください。
- 参照画像と採用画像はダウンロードできます。アプリの画像候補を消す操作は用意していません。

## 保存先とデータ

プロジェクトの標準保存先はリポジトリ内の `data/projects/<UUID>.json` です。
JSONはUTF-8で日本語をそのまま保存し、タイトルをファイル名に使わないため、同名の企画も保存できます。
一時ファイルに書いてから置き換え、保存途中の失敗で既存のJSONが壊れることを防ぎます。
壊れたJSONは一覧に警告を表示し、正常なファイルは引き続き読み込みます。

ストーリーは `data/projects/<UUID>/story_history.json` に別保存します。
取り込み・ページ編集・復元のたびに、UUID・UTC日時・操作種別・ストーリー全体を記録します。最新の版が現在のストーリーです。
既存のプロジェクトJSONを移行する作業は不要です。プロジェクトを開くと対応する履歴を読み込みます。
同時保存はmacOS/Linux標準のファイルロックと版IDの確認で保護します。保存競合が表示された場合は、最新の内容を確認してからやり直してください。
履歴が壊れている場合は警告を表示し、上書きを停止します。手動で内容を削除せず、バックアップから復旧してください。

第3段階のデータも同じローカルの保存領域に配置します。

```text
data/projects/
├── <プロジェクトID>.json
└── <プロジェクトID>/
    ├── story_history.json     # 第2段階のストーリー履歴
    ├── editorial.json         # 参考作品・分析・評価・脚本確定の履歴
    ├── artwork.json           # キャラクター、作風、作画指示、候補・採用の記録
    ├── composition.json       # ページ設定・コマ割り・吹き出しと編集前の履歴
    ├── assistant.json         # 制作提案・確認・採用・作画評価の履歴
    ├── assistant_pending.json # 採用保存の変更前後・再開状態
    └── images/
        ├── references/        # キャラクターの参照画像（UUID.png）
        └── panels/            # コマの候補画像（UUID.png）
```

画像はMacで実行していればMac上のこのフォルダに保存されます。クラウドで動かしたアプリはクラウド上に保存します。
候補画像はページ番号・コマ番号に紐づけ、登録時のストーリー版とコマ内容も記録します。採用の変更履歴もJSONに残します。
第1・第2段階のデータはそのまま利用でき、既存JSONの移行操作は不要です。
既存のキャラクター・作画設定・画像も変更しません。参考作品・分析・評価はプロジェクト別の `editorial.json` に保存し、
改善の対応情報だけを `story_history.json` の版メタデータに追加します。受け渡すストーリーJSONの形式は変更しません。
設定JSONだけをコピーすると画像は含まれないため、必ずプロジェクトのフォルダ全体をバックアップしてください。
保存はファイルロックと版番号の確認を使い、保存失敗時は既存のJSON・画像を維持します。

`data/projects/` 内の利用者データはGit管理対象外です。バックアップにはフォルダ全体を別の場所へコピーしてください。
履歴は増えていくため、必要に応じてバックアップとディスク空き容量を確認してください。
保存先を変更するときは、起動前に環境変数を設定します。相対パスは起動したフォルダが基準になるので、絶対パスを推奨します。

```bash
export MANGA_DATA_DIR="$HOME/Documents/manga-projects"
python -m streamlit run app.py --server.address 127.0.0.1
```

主なJSON項目は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| `schema_version` | JSON形式のバージョン（現在は1） |
| `id` | プロジェクトを識別するUUID |
| `title`, `genre`, `synopsis`, `page_count` | 入力した企画 |
| `created_at`, `updated_at` | UTC・タイムゾーン付きの作成／更新日時 |
| `workflow` | 将来の工程・完了済み工程・成果物パスの保存領域 |
| `budget` | 第1段階との互換用項目。現在の手動連携では未使用 |

`workflow` は将来の工程管理用で、現在は保存・再読み込みだけを行います。
ストーリーは保存済みの最新履歴から編集を再開できます。自動生成処理の再開機能はありません。
未対応の `schema_version` は読み込み時に警告となります。将来形式を変える際は、データ移行処理を追加する想定です。

## 漫画ページを編集・出力する（第4段階）

1. プロジェクトを開き、ストーリーJSONを保存します。「生成画像・採用一覧」で必要なコマ画像を採用しておきます。画像がないコマも灰色のプレースホルダーで編集・出力できます。
2. 下部の「漫画ページ編集・出力」で「合成するページ」を選びます。ページ数・コマ数は企画ではなく、現在のストーリーJSONから取得します。1ページ1〜6コマ、通常は3コマです。
3. 「出力サイズ・余白・日本語フォント」で横幅（600・1080・1600・2000px）、縦横比（縦長2:3・A判・正方形）、余白、コマ間隔、枠線、DPIを選び、「ページ共通設定を保存」を押します。寸法はピクセル数で決まり、DPIはPNG・PDFの物理寸法に使います。
4. 「コマ割りを編集」でテンプレートを選び、「このページのコマ割りを保存」を押します。「縦積み」「2列・右→左」「上段を大きく・下段は右→左」「右側を大きく・左側は上→下」の4種類です。**コマ番号が読む順序**です。
5. 細かく調整する場合は「コマの配置を手動調整」をオンにし、位置・幅・高さを%で指定して保存します。コマの座標はページ余白の内側が基準です。重なり・枠外・極端に小さいコマはエラーになります。手動配置ではコマ間隔も座標で調整してください。
6. 「セリフ・吹き出しを編集」で対象を選び、楕円／四角、縦書き／横書き、位置、サイズ、しっぽ、文字サイズ上限を変更し「吹き出しを保存」を押します。位置は対象コマの枠線の内側が基準です。各コマにセリフ・ナレーションの枠を用意し、空の本文は描画しません。
7. 本文は標準でストーリーに追従します。「この吹き出し専用の文章を使う」をオンにすると、その吹き出しだけ文章を編集できます。「吹き出しを追加」で別のセリフや自由文を増やせます（1ページ60個まで）。不要なものは「この吹き出しを表示」をオフにします。元の脚本は変わりません。話者名を消したい場合や会話を分割したい場合も専用文を使います。
8. 「ページをプレビュー・再描画」を押します。以後はページ切替・保存後に表示を更新します。プレビューは最大600pxです。変更していないコマは容量上限32MiBのセッション内キャッシュを使い、変更したコマだけを描き直してページに配置します。再起動後は再描画します。
9. 出力形式を選び「出力ファイルを生成」→「完成ファイルをダウンロード」を押します。保存済みの設定・画像が対象です。設定やページ・採用画像が変わると古いダウンロードは消え、再生成できます。

フルカラー・透過画像に対応します。画像は縦横比を維持して枠内へ収め、**トリミングしません**。比率が異なる場合は白い余白ができます。元の画像ファイルへ上書きしません。
ページや吹き出しの編集は数値入力です。ドラッグ操作・ルビ・禁則処理・縦中横などの専門的な組版には未対応です。

### 日本語フォントと文字の収まり

Macでは標準のヒラギノ、Linuxではインストール済みのNoto CJKなどを自動検出します。
見つからない場合は、利用可能な日本語TTF・OTF・TTC・OTCの**ファイルパス**を共通設定へ入力してください。
Macの例は `/System/Library/Fonts/ヒラギノ角ゴシック W3.ttc` です。OSによって場所が違う場合はFont Bookで実ファイルを確認します。
環境変数 `MANGA_FONT_PATH` でも指定できます（プロジェクトの指定が優先）。フォントは自動ダウンロード・同梱しません。

フォントの文字表を検証し、日本語を描けないフォントや、絵文字・異体字など未対応の文字は具体的なエラーにします。
文章は自動改行・縮小して配置し、最小サイズ（出力横幅の約0.8%、下限5px）でも収まらなければ出力を停止します。
本文を省略したり、文字化けしたまま出力したりしません。枠を広げる・文を分ける・短くすることで調整してください。
縦書きは上→下、列は右→左。句読点・括弧の縦用字形や長音の回転を扱い、RAQMなどの追加ネイティブライブラリは不要です。
プレビューと実寸では丸めの違いがあるため、出力時にも文字の収まりを検証します。

### 出力形式

| 形式 | 内容 |
| --- | --- |
| 表示中ページのPNG | 設定サイズの1ページ。DPI情報を含むフルカラーPNG |
| 全ページのPNG（ZIP） | `page_001.png` からページ番号順に格納 |
| 全ページのPDF | 全ページを1ファイルに格納。日本語も画像化したPDFなので、閲覧先でのフォント設定は不要（文字選択は不可） |
| 縦読みSNS画像（ZIP） | 横幅600／1080px、ページ順・コマ番号順に1列へ再配置。吹き出しも再描画。コマを途中で切らず、高さ8000px以内のPNGへ分割。対応表 `reading_order.json` を同梱 |

PDFは各ページの閲覧順が1、2、3…となります。見開きの綴じ方向や印刷用トンボは設定しません。
縦読みは全ページまたは表示中ページだけを選べます。コマの縦横比を保つため、極端に縦長のコマは調整を求めます。
メモリ使用量を抑えるため、一度の全ページ・縦読み出力は合計6000万画素までです。上限時は横幅を小さくするか、ページ単位で出力してください。
完成ファイルはブラウザからMacへダウンロードします。アプリの保存領域に完成ファイルを自動蓄積しません。

### 編集データと既存データの保護

ページ設定はプロジェクト別の `composition.json` に分離し、ストーリー・キャラクター・参考作品・候補画像のJSON形式は変えません。
設定の保存ごとに編集前の内容を `history` に残し、ファイルロックと版番号で保存競合を防ぎます。
JSONが壊れている場合は上書きを停止します。バックアップはアプリを終了して**保存先フォルダ全体**をコピーしてください。
`history` は復旧用の記録で、この版にはページ設定の履歴復元ボタンはありません。復旧時も元ファイルのコピーを保管してから作業してください。

脚本変更後は、コマ数が同じなら配置を引き継いで本文を更新し、異なる場合は一時的な自動配置を使います。
画面・出力時に不整合の可能性を通知します。専用の文章や採用画像は自動変更しないため、確認して保存し直してください。
以前の配置は保存時の履歴に残り、減ったページやコマの画像も削除しません。

## AI制作アシスタント（第5段階）

ストーリー保存後、画面下部の「AI制作アシスタント」を使えます。AIへの送信と返答の受け取りは引き続き手動です。
**依頼作成やJSON取り込みだけでは、既存の確定設定は変わりません。**

### 共通の使い方

1. プロジェクトを開き、必要なら「制作テーマ・補足」を入力します。不明なら空欄で構いません。
2. A〜Dから支援機能を選び、「○○の依頼を作成」を押します。ストーリー版、依頼ID、対象コマ、既存設定のスナップショットとプロンプトを保存します。
3. 「ChatGPTへ渡すプロンプト」の右上のコピーを使い、自分でChatGPTに貼り付けます。返答形式もプロンプトに含まれます。
4. 返答JSONを貼り付けるか、UTF-8のJSONファイルを取り込みます。Markdownのコードフェンス、UTF-8 BOMにも対応します。上限は1MBです。
5. 「提案一覧と既存内容の比較」で全件を確認します。「確認・編集する提案」を選ぶと実際の差分と確認事項を表示します。「選んだ提案だけ編集」で必要な箇所を直し、**提案の編集を保存**します。この時点でも既存設定は変わりません。
6. 「採用候補」のチェックを付けます。1件ずつ、または「確認待ちをまとめて選択」で全件を選べます。確認事項と差分を確認した承認チェックを付け、「選択した提案を採用」で初めて確定設定に反映します。
7. 不要な提案はチェックして「選択した提案を見送る」を押せます。見送ったものを確認待ちへ戻すこともできます。未選択の設定・画像は変更しません。

最新依頼の進行状態は「未作成・提案待ち・確認待ち・採用済み・見送り」などで表示します。
依頼ごとに複数の返答を保存でき、「表示する生成依頼」「表示する提案履歴」で以前の候補も閲覧できます。
採用済みの同じ提案を再採用して二重登録することはできません。新しい改善は新しい依頼・提案として保存します。
フォームの未保存内容は依頼・提案を切り替える前に保存してください。

### A：キャラクター一括生成

保存済みストーリーと既存人物の設定をChatGPTへ渡し、登場人物・外見・性格・身長・役割・視覚的な差別化を提案させます。
各非空項目の `provenance` に「ストーリー明記／AI提案／要確認」と根拠を持たせ、表で区別します。アプリで変更した項目は「ユーザー編集」として記録します。
AIが「明記」とした根拠も、アプリが作品内容を独立に検証したものではありません。採用前に確認してください。

既存人物の更新には `existing_id` を指定し、新規人物は `null` にします。確認画面の「反映先の人物」で変更できます。
既存人物を選ぶとそのID・参照画像・基準画像を維持して設定だけを更新します。新規IDはアプリが発行します。
同名候補は警告し、通常は登録を止めます。表記の全角・半角、大小文字、空白の差も重複候補として扱います。
別人を意図している場合だけ「同名候補がある場合も別の人物・作品として登録する」を選びます。
空の項目や確認事項は自動で推測補完しません。AIが新たに設計した設定は「AI提案」として扱います。

### B：参考作品候補

ジャンル・あらすじ・テーマ補足と既存参考作品から、漫画・小説・映画・アニメなどを提案させます。
参考理由、抽象的な技法、演出方法、自作への応用、確認状態と根拠を表示します。
AI返答は必ず「要確認」で取り込みます。「ユーザー確認済み」への変更は、利用者が内容を確かめてから確認・編集画面で行ってください。
確認状態はアプリによる事実確認を意味しません。未確認の作品情報は断定せず、固有の人物・台詞・展開の再現を避けます。
採用したものだけを既存の参考作品へ新規登録します。応用・確認状態・根拠は「メモ」に引き継ぎ、既存作品は上書きしません。
同じ作品名・媒体は通常重複登録を止めます。登録後は既存の参考作品管理・分析機能で編集・分析できます。
URLへアクセスしたり、外部サイトをスクレイピングしたりする処理はありません。

### C：作画指示一括生成

「出力対象」で**全コマ・指定ページ・指定コマ**を選べます。通常の8ページ24コマをまとめて依頼できます。
返答が長くなる場合はページ単位に分け、それぞれ依頼を作成してください。指定対象の一部が欠けたJSONはエラーになります。
ストーリー、登録人物、作風、既存指示を渡し、場所・時間帯・表情・ポーズ・カメラ・構図・背景・光・色彩・演出的役割・連続性を提案させます。
人物は登録済みのUUIDで指定します。新しい人物が必要ならAで採用してからCの依頼を作り直してください。

採用するコマだけにチェックを付けると、そのコマの指示だけを保存します。未採用コマ、候補画像、採用画像とその履歴は保持します。
採用画像があるコマの指示変更では、画像との不整合を警告します。画像一覧・ページプレビューでも、登録時の作画条件との変更を通知します。
画像は自動再生成しません。必要な画像をChatGPTで作り直し、従来の画像管理画面で候補登録・採用してください。

### D：作画評価・改善

対象コマに保存済みの有効な作画指示がある状態で評価依頼を作ります。未設定・脚本変更後の古い指示には確認を求めます。
評価は、整合性、構図、感情、表情・ポーズの自然さ、カメラ、連続性、人物の一貫性、読みやすさの8項目（0〜10点）です。
良い点・問題点・理由・改善案・対象ページとコマを保存し、100点換算の平均参考点も表示します。
**AIの採点は主観的な参考値で、作品の品質を保証しません。** ストーリー評価とは別に管理します。

評価JSONを取り込むと、評価を選んで全コマ・ページ・コマ単位の改善依頼を作れます。
返ってきた改善JSONもCと同じ確認・編集・選択採用を通します。元テーマ・世界観・人物設定・作風を維持するプロンプトです。
改善採用後は、新しい評価依頼を作って再評価します。「改善前後の作画評価・指示を比較」で各項目の得点差と、評価時点のJSONに基づく実際の指示差分を確認できます。
改善理由・原案・編集・採用時の変更前後は各提案の履歴に残ります。自動反復や自動送信は行いません。

### E：画像プロンプト一括出力

保存済みの有効な作画指示から、ページ・コマ番号付きの画像生成用プロンプトを一覧表示します。
共通作風（フルカラー等）、コマの文脈、人物外見、各作画項目、参照画像を手動添付する案内、文字・吹き出しを描かない指示を含みます。
各枠右上から1コマずつコピーでき、全件を `manga_image_prompts.txt` としてダウンロードできます。
未設定、脚本変更後の未確認の指示、削除済み人物のあるコマは出力せず、不足情報と必要な操作を表示します。
コピー・ChatGPTへの貼り付け・参照画像の添付・画像のダウンロードとアプリへの登録は、利用者が手動で行います。

### APIなしで試すサンプル

各機能で依頼を作り、「返答形式を確認」→「動作確認用の返答サンプルJSON」をダウンロードします。
現在の依頼ID・ストーリー版・人物IDに対応するため、ChatGPTを開かずにそのまま取り込み→提案編集→選択採用を試せます。
サンプルは架空のデモ設定・仮評価です。実作品へ採用する場合は必要な内容へ修正してください。
固定IDを使った形式例も [examples/assistant/](examples/assistant/) に5種類保存しています。固定例は任意の企画へそのまま取り込めません。

返答の共通項目は `schema_version`, `project_id`, `request_id`, `story_version_id`, `kind` です。生成プロンプトの値を変更しないでください。
提案は `items`、評価は `scores` と `summary` に分離します。必要なキーは返答ひな形を参照し、不明な設定は空文字、確認事項は `questions` の配列に記載します。
人物・提案IDの重複、対象外・欠番・欠けたコマ、存在しない人物ID、範囲外の評価点、不正なJSON・重複キーは保存前に検出します。

### 保存・互換性・途中失敗時の扱い

- `assistant.json`：依頼、プロンプト、対象ストーリー版と設定のスナップショット、提案原案・編集、採用状態、作画評価、改善・採用時の変更前後を保存します。
- `assistant_pending.json`：最後の採用保存の再開記録です。変更前後のJSONを持ち、完了後も `done` として残します。手動で削除しないでください。
- 採用先は既存の `artwork.json` または `editorial.json` です。`story_history.json`、`composition.json`、画像ファイルは変更しません。追加項目がない旧JSONもそのまま利用でき、移行操作は不要です。

取り込み・採用時に最新のストーリー版を確認します。依頼後に人物・作風や対象の作画指示を変更した場合も、その提案の取り込み・採用や評価利用を止め、新しい依頼を求めます。
一部採用後に残りの未変更コマを採用することはできますが、同じ古い依頼から別の返答を取り込む場合は依頼を作り直してください。
参照画像の追加だけでは人物の外見を上書きせず、最新の参照画像を保持して人物設定を採用できます。

保存はファイルロックと版番号で競合を検出し、一時ファイルからJSONを置き換えます。
2つのJSONにまたがる採用は、承認した変更を再開記録へ先に保存してから反映します。
途中で失敗すると片方だけが反映済みの場合があります。画面を更新し、「採用保存を再開」を押して完了してください。それまでは他画面の編集を避けます。
再開は二重登録を防ぎ、途中に別の編集があれば上書きを停止します。その場合は**保存フォルダ全体をバックアップ**し、再開記録と各JSONの差分を確認してください。
破損JSONも上書きせずエラーにします。履歴は増えるため、定期的にアプリを終了して保存先全体をバックアップしてください。

## テスト

仮想環境を有効にした状態で実行します。

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

テストは一時フォルダを使うため、実際の保存データを書き換えません。
JSONの日本語保存・読み込み、更新、同名プロジェクト、入力エラー、不正なJSON、保存失敗時の保護を確認します。
StreamlitのAppTestでは、入力→保存→編集→新しいセッションでの再読み込みまで確認します。
第2段階では、JSONの表記揺れと入力エラー、UTF-8ファイルの読み込み、プロンプトの内容、履歴の復元・破損・同時保存を検証します。
外部通信を禁止したAppTestで、貼り付け→ページ編集→復元→再起動後の再読み込みも確認します。
第3段階ではキャラクターの登録・編集・削除、参照画像の基準選択、画像の形式・サイズ・透過・向き、
コマ別指示とプロンプト、候補の採用変更と保持、保存失敗・競合・破損設定の保護を確認します。
AppTestの画像アップロードはファイル選択の入力部分だけを模擬し、その後の検証・PNG化・保存・再読み込みは実際の処理を通します。
参考作品と分析の版管理、評価の対象・採点・総合点換算、3方式の改善、部分改善の範囲外変更拒否、
繰り返し改善、実際のJSON差分、採用時の評価対応、脚本確定後の変更通知もテストします。
外部通信を禁止したAppTestで、参考分析→評価→部分改善→再評価→差分確認→確定→変更通知→過去版採用→再読み込みを検証します。
ページ合成では、テンプレートの読み順・非重複、画像の両端・色・透過の保持、日本語の縦横書き、未対応文字・文字溢れの拒否、編集履歴・競合・破損JSONの保護を検証します。
PNGの実寸・PDFの全ページ数と色・縦読みの順序と分割、変更コマだけのキャッシュ更新、元データが不変であることも確認します。
外部通信を禁止したAppTestでコマ割り・吹き出し編集→保存→プレビュー→PNG/PDF出力→再読み込みを検証します。
テスト環境にも日本語フォントが必要です（Macはヒラギノ、Ubuntu等はfonts-noto-cjk）。
第5段階では、提案JSON・人物根拠・対象版・人物IDの検証、部分採用、同名・重複ID・保存競合・同時採用を検証します。
参照・採用画像やページ設定の保持、採用先と提案の保存途中失敗・明示再開・二重登録防止、作画の評価→部分改善→再評価と画像プロンプトの全件出力も確認します。
外部通信を禁止したAppTestで、新しい5機能の依頼・貼り付け／ファイル取り込み・提案編集・承認・見送り・再読み込みまで実行します。
テストにもAPIキーや外部APIへの接続は必要ありません。

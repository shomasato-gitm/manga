# AI漫画スタジオ（第3段階）

漫画の企画を保存し、**ユーザーがChatGPTと手動で受け渡しして**ストーリーを制作するStreamlitアプリです。
プロジェクト作成に加え、プロンプト生成、ストーリーJSONの取り込み、ページ単位の編集、履歴の保存・復元ができます。
第3段階ではキャラクター設定・参照画像、コマ別の作画指示、画像生成用プロンプト、候補画像の登録・採用を管理します。

**OpenAI API・非公式API・ChatGPTのWeb画面の自動操作は一切使用しません。APIキーは不要です。**
アプリからAIサービスへの通信は行わず、APIによる追加課金は発生しません。
ChatGPTへの貼り付けと返答のコピーはユーザーがご自身のWeb画面で行います。ChatGPT側の利用制限は契約プランに従います。
画像生成はユーザーがChatGPTで行います。アプリは生成された画像をローカル保存し、漫画ページの自動合成・PNG/PDFページ出力は行いません。

## Intel Macでの準備

推奨環境は **Intel Mac・macOS 10.15〜12・Python 3.11** です。
主要な依存パッケージを、古いIntel Mac向けのバイナリ配布があるバージョンに固定しています。
Python 3.9〜3.12に対応する構成ですが、まずは3.11を利用してください。
macOS 10.14以前はPyArrowの配布対象外のため、この構成では対応しません。
Mac実機での動作確認は未実施です。

1. Pythonがなければ [Python公式のmacOSダウンロード](https://www.python.org/downloads/macos/) から、macOSの対応条件を確認してPython 3.11をインストールします。OS付属のPythonは変更しません。
2. ターミナルを開き、ダウンロードまたはcloneした `manga` フォルダに移動します。
3. 以下を1行ずつ実行します。`.venv` は、このアプリ専用のPython環境です。

```bash
cd /path/to/manga
python3.11 --version
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py --server.address 127.0.0.1
```

`/path/to/manga` は実際のフォルダのパスに置き換えてください。
ブラウザが自動で開かなければ、ターミナルに表示されるLocal URLをブラウザで開きます。
終了するにはターミナルで `Control + C` を押します。
次回からはフォルダに移動し、`source .venv/bin/activate` と起動コマンドだけで起動できます。

すでに第1・第2段階を利用している場合は、アプリを終了してデータフォルダをバックアップした後、
`git pull --ff-only` でコードを更新して再起動してください。第3段階の追加パッケージはありません。

Pythonのコマンドが見つからない場合はインストール後にターミナルを開き直し、`python3.11 --version` を確認してください。
証明書エラーが出る場合、python.orgのインストーラーに付属する `Install Certificates.command` を実行します。証明書検証を無効にする必要はありません。
別のアプリがポートを使用している場合は、起動コマンドの末尾に `--server.port 8502` を追加できます。

## プロジェクトの作成・再読み込み（既存機能）

1. タイトル・ジャンル・あらすじを入力します。ページ数は初期値8、指定範囲は1〜100です。
2. 「プロジェクトを保存」でJSONファイルが作成されます。
3. 左側の一覧から選び、「選択したプロジェクトを開く」で再読み込みします。
4. 読み込んだ内容を変更して保存すると、同じプロジェクトを更新します。
5. 「新規プロジェクト」でフォームを空にすると、別のプロジェクトを作成できます。同じタイトルでも別々のIDで管理します。

一覧の「開く」や「新規プロジェクト」は未保存の入力を置き換えます。必要な内容は先に保存してください。
JSONのダウンロードは最後に保存した内容が対象です。フォームの未保存内容は含みません。
この版は個人がローカルで使う想定です。同じプロジェクトを複数の画面で同時に編集すると、最後の保存が反映されます。

## ChatGPTとストーリーを作る手順

1. プロジェクトを作成・保存するか、一覧から開きます。通常は8ページにします。
2. 下部の「ChatGPT用プロンプト」を開きます。保存済みの設定から、全ページ・各ページ3コマを想定したプロンプトが自動で作られます。
3. プロンプト枠の右上にある**コピーボタン（重なった四角。マウスを重ねると表示）**を押します。Streamlit標準のコピー機能です。必要なら枠内を選択して手動コピーもできます。
4. ご自身でChatGPTを開き、新しい会話に貼り付けて送信します。
5. 返されたJSONをコピーし、アプリの「JSON取り込み」→「貼り付け」に貼り付けます。またはUTF-8の `.json` ファイルに保存し、「JSONファイル」から選びます。
6. 「検証してストーリーを保存」を押します。形式やページ数が不正なら、問題の場所を表示し、既存ストーリーは変更しません。成功すると新しいバージョンとして保存します。
7. 「ページ編集」でページを選び、概要、各コマの描写・セリフ・ナレーションを編集します。「このページを保存」で、他のページを保ったままストーリー全体を履歴保存します。タイトルと全体のあらすじも編集できます。
8. 評価・改善したい場合は「ChatGPT用プロンプト」の下部で改善希望を入力し、評価・改善用プロンプトをコピーします。ChatGPTからの返答のうち、改善版JSONを再び取り込んでください。
9. 元に戻す場合は「バージョン履歴」で過去版を選び、内容を確認して「このバージョンを復元」を押します。復元も新しい版として保存するため、それまでの履歴は消えません。

プロンプト・JSONのダウンロードは**最後に保存した内容**が対象です。
ページやプロジェクトの切り替え、新しい取り込み、履歴の復元の前に、編集中の内容を保存してください。
フォームの未保存内容は引き継がれません。
企画のページ数を変更しても既存ストーリーは自動で増減しません。画面に差異を表示し、次の取り込みでは新しい設定ページ数を検証します。

### ChatGPTなしで取り込みを試す

8ページのプロジェクトを保存して、[examples/story_8pages.json](examples/story_8pages.json) を取り込むと、24コマのサンプルを編集できます。
自分でJSONを作る場合は、画面の「JSONひな形をダウンロード」も利用できます。ひな形の記入用の文は実際の内容に置き換えてください。

### 受け渡すストーリーJSON

| 項目 | 形式・内容 |
| --- | --- |
| `schema_version` | 1。省略時も1として扱う |
| `title` | タイトル（100文字以内）。省略時はプロジェクトのタイトル |
| `summary` | 全体のあらすじ（4000文字以内）。省略可 |
| `pages` | 設定したページ数の配列。通常8ページ、1から順に並べる |
| `pages[].page` | 1からのページ番号 |
| `pages[].summary` | ページ概要（2000文字以内）。省略可 |
| `pages[].panels` | コマの配列。目安3コマ、1〜6コマを許可。3以外は警告を表示 |
| `panels[].panel` | 各ページ内で1からのコマ番号 |
| `panels[].description` | 必須の描写（4000文字以内） |
| `panels[].dialogue` | 話者を含むセリフの文字列（4000文字以内）。省略可 |
| `panels[].narration` | ナレーション（2000文字以内）。省略可 |

多少の出力の揺れは、取り込み時に次のように正規化します。

- JSONの前にUTF-8 BOMがあっても読み込みます。説明文の中に1つだけある ` ```json ` コードブロックも読み込めます。
- `{"story": {...}}` や `{"ストーリー": {...}}` の外側のオブジェクトを許可します。
- `タイトル`、`あらすじ`、`ページ`、`ページ番号`、`概要`、`コマ`、`コマ番号`、`描写`、`セリフ`、`ナレーション` などの日本語キーを許可します。
- `page_number` / `panel_number`、描写の `scene`、セリフの `dialogues` にも対応します。
- ページ・コマ番号が省略されていれば配列順から補います。`"1"` などの数字文字列も整数に変換します。
- セリフは文字列の配列、または `{"speaker": "話者", "text": "セリフ"}` の配列でも取り込めます。話者の `character` / `話者`、本文の `セリフ` も使えます。改行区切りの文字列として保存します。
- 任意の本文項目の省略・`null` は空文字列にします。未知の項目は保存せず、項目名を警告します。必要な情報なら対応項目に移してください。

番号の重複・欠番、ページ数の不一致、空の描写、同じ意味の項目の矛盾、未対応のバージョンはエラーです。
複数のコードブロックは1つに絞ってください。JSONは1MB以下・UTF-8形式とし、全角引用符、コメント、末尾の余分なカンマは修正してください。

## キャラクター・コマ画像を作る手順（第3段階）

プロジェクトを開くと、下部に「キャラクター・作画・画像管理」が表示されます。
作画指示とコマ画像の登録には、第2段階で保存したストーリーが必要です。キャラクターはストーリー取り込み前にも登録できます。

### 1. 作風とキャラクターを登録する

1. 「プロジェクトの作風」に、白黒／カラー、線画、塗り、雰囲気などを入力して「作風を保存」を押します。作風はこのプロジェクトの各プロンプトに共通で反映します。
2. 「キャラクター設定」→「新規キャラクター」で名前・年齢・性別・髪型・髪色・目の色・体格・服装・性格・特徴を入力し、「キャラクターを保存」を押します。名前のみ必須です。年齢は「17歳」「不明」などの文字列で入力できます。
3. 別の人物を追加するときは再び「新規キャラクター」を選びます。既存の人物を選択して保存すると、その人物を更新します。同名の人物も別々に管理できます。
4. 削除する場合は「キャラクターを削除」を開き、対象名を確認してチェックを入れ、「このキャラクターを削除」を押します。

削除は一覧から非表示にする方式です。参照画像・候補画像・登録時の人物設定を残すため、ディスク上の画像は削除しません。
削除した人物を使っている作画指示は警告となるため、登場キャラクターを選び直して保存してください。

### 2. キャラクターの基準画像を作る

1. 保存した人物を選び、「生成する向き・種類」を正面・斜め・全身・表情差分から選び、表情を指定します。
2. 表示された日本語プロンプトを右上のコピーボタンでコピーし、ご自身でChatGPTへ貼り付けて画像を生成します。
3. ChatGPTで画像をダウンロードし、アプリの「キャラクターの参照画像」から選びます。種類とメモを入力して「参照画像を保存」を押します。
4. 正面・斜め・全身・表情差分などを繰り返し登録できます。最初の画像を基準画像とし、「基準にする参照画像」→「基準画像を選択」で変更できます。
5. 別の画像を生成するときは、参照画像をアプリからダウンロードし、ChatGPTへ**手動で添付**してください。プロンプト内のファイル名はアプリからダウンロードしたPNGの名前と一致します。

プロンプトをコピーしただけでは画像は送信されません。基準画像や補助画像も同じChatGPTの会話に添付してください。
同じ外見を保つための指示は含めますが、実際に生成された顔立ち・服装などはユーザーが目で確認します。

### 3. コマごとの作画指示とプロンプトを作る

1. 「コマの作画指示」でページ・コマを選びます。保存済みストーリーの描写・セリフ・ナレーションが表示されます。
2. 登場キャラクターを選び、場所・時間帯・表情・ポーズ・カメラ角度・構図を設定します。複数人の場合は「ルナ：笑顔、ソラ：驚き」のように表情を指定できます。
3. 「このコマの作画指示を保存」を押します。指示はストーリーJSONを変更せず、別に保存します。
4. 作風・キャラクター設定・作画指示・ストーリーを組み合わせた日本語プロンプトが表示されます。コピーして、人物の参照画像と一緒にChatGPTへ渡してください。

プロンプトは外見の統一を指示し、**セリフ・吹き出し・文字・ナレーションを画像に描き込まない**方針です。
セリフは場面の意味を伝える参考情報として渡します。登場キャラクターを選ばない場合は、人物を追加しない背景中心の指示になります。
未保存の設定はプロンプトに反映しません。画面やコマの切り替え前に保存してください。

### 4. コマ画像を登録・採用する

1. 「生成画像・採用一覧」で対象のページ・コマを選び、ChatGPTからダウンロードした画像を選択します。
2. 「候補画像を保存」で登録します。同じコマに複数の候補を追加できます。同じファイル名でも上書きしません。
3. 候補を見比べ、「採用候補を選ぶ」→「選んだ候補を採用」を押します。新規登録だけでは採用になりません。
4. 下部の「○ページの採用画像一覧」で、各コマの採用状況を確認します。未採用のコマも表示します。これは一覧表示であり、ページ画像の自動合成ではありません。

採用を変更しても過去の候補は削除しません。候補ごとの「登録時の作画条件」で、その時の描写・作風・人物・作画指示を確認できます。
この記録は登録時点のアプリの設定で、ChatGPTで実際に使ったプロンプトを自動取得するものではありません。

ストーリーのコマ内容を変更すると、以前の作画指示・画像に警告が付きます。指示を確認して保存し直すと、現在の内容に結び直せます。
以前の画像を採用する場合は、警告を確認して選んでください。
コマ数・ページ数を減らしても画像は残り、「現在のストーリーにないコマの画像履歴」から確認できます。
作風やキャラクターの変更後も画像は自動再生成しません。必要に応じて新しい候補を追加します。

### 取り込める画像

- PNG・JPEG・WebPの静止画。1ファイル20MB・2400万画素以下です。アニメーションやHEICは取り込めません。
- 拡張子だけでなくPillowで画像の内容を検証し、向きの情報を反映したPNGとして保存します。
- 透過画像は透過を維持し、EXIFや画像内コメントなどのメタデータは保存時に除きます。元のダウンロード画像そのものは変更しません。
- 変換後に20MBを超える画像もエラーになります。その場合は元の画像を小さくして再登録してください。
- 参照画像と採用画像はダウンロードできます。アプリの画像候補を消す操作は用意していません。

## 保存先とデータ

プロジェクトの標準保存先はリポジトリ内の `data/projects/<UUID>.json` です。
JSONはUTF-8で日本語をそのまま保存し、タイトルをファイル名に使わないため、同名の企画も保存できます。
一時ファイルに書いてから置き換え、保存途中の失敗で既存のJSONが壊れることを防ぎます。
壊れたJSONは一覧に警告を表示し、正常なファイルは引き続き読み込みます。

ストーリーは `data/projects/<UUID>/story_history.json` に別保存します。
取り込み・ページ編集・復元のたびに、UUID・UTC日時・操作種別・ストーリー全体を記録します。最新の版が現在のストーリーです。
既存のプロジェクトJSONを移行する作業は不要です。プロジェクトを開くと対応する履歴を読み込みます。
同時保存はmacOS/Linux標準のファイルロックと版IDの確認で保護します。保存競合が表示された場合は、最新の内容を確認してからやり直してください。
履歴が壊れている場合は警告を表示し、上書きを停止します。手動で内容を削除せず、バックアップから復旧してください。

第3段階のデータも同じローカルの保存領域に配置します。

```text
data/projects/
├── <プロジェクトID>.json
└── <プロジェクトID>/
    ├── story_history.json     # 第2段階のストーリー履歴
    ├── artwork.json           # キャラクター、作風、作画指示、候補・採用の記録
    └── images/
        ├── references/        # キャラクターの参照画像（UUID.png）
        └── panels/            # コマの候補画像（UUID.png）
```

画像はMacで実行していればMac上のこのフォルダに保存されます。クラウドで動かしたアプリはクラウド上に保存します。
候補画像はページ番号・コマ番号に紐づけ、登録時のストーリー版とコマ内容も記録します。採用の変更履歴もJSONに残します。
第1・第2段階のデータはそのまま利用でき、既存JSONの移行操作は不要です。
設定JSONだけをコピーすると画像は含まれないため、必ずプロジェクトのフォルダ全体をバックアップしてください。
保存はファイルロックと版番号の確認を使い、保存失敗時は既存のJSON・画像を維持します。

`data/projects/` 内の利用者データはGit管理対象外です。バックアップにはフォルダ全体を別の場所へコピーしてください。
履歴は増えていくため、必要に応じてバックアップとディスク空き容量を確認してください。
保存先を変更するときは、起動前に環境変数を設定します。相対パスは起動したフォルダが基準になるので、絶対パスを推奨します。

```bash
export MANGA_DATA_DIR="$HOME/Documents/manga-projects"
python -m streamlit run app.py --server.address 127.0.0.1
```

主なJSON項目は次のとおりです。

| 項目 | 内容 |
| --- | --- |
| `schema_version` | JSON形式のバージョン（現在は1） |
| `id` | プロジェクトを識別するUUID |
| `title`, `genre`, `synopsis`, `page_count` | 入力した企画 |
| `created_at`, `updated_at` | UTC・タイムゾーン付きの作成／更新日時 |
| `workflow` | 将来の工程・完了済み工程・成果物パスの保存領域 |
| `budget` | 第1段階との互換用項目。現在の手動連携では未使用 |

`workflow` は将来の工程管理用で、現在は保存・再読み込みだけを行います。
ストーリーは保存済みの最新履歴から編集を再開できます。自動生成処理の再開機能はありません。
未対応の `schema_version` は読み込み時に警告となります。将来形式を変える際は、データ移行処理を追加する想定です。

```text

├── .streamlit/config.toml  # ローカル起動・利用統計の送信を無効化
├── manga/
│   ├── models.py           # プロジェクトの定義と入力チェック
│   ├── storage.py          # JSONの保存・一覧・読み込み
│   ├── prompts.py          # 手動連携用プロンプトの作成
│   ├── story.py            # ストーリーJSONの検証・正規化
│   ├── story_storage.py    # 履歴の保存・復元
│   ├── story_ui.py         # 取り込み・編集・履歴の画面
│   ├── artwork_models.py   # キャラクター・作画設定の項目と検証
│   ├── artwork_storage.py  # 作画設定と参照・候補画像の保存
│   ├── artwork_ui.py       # 第3段階の画面
│   ├── image_prompts.py    # キャラクター・コマ画像用プロンプト
│   ├── images.py           # 画像の検証・PNG化
│   └── services/README.md  # 今後の出力処理の追加先
├── data/projects/          # 企画・ストーリー・作画設定・画像（Gitには含めない）
├── examples/               # 8ページ・24コマの取り込み用サンプル
├── tests/                  # データと画面の自動テスト
├── requirements.txt        # 実行に必要なパッケージ
├── requirements-dev.txt    # テストを含む開発用パッケージ
└── pytest.ini              # テスト設定
```

APIキーの入力・読み込み・保存機能はありません。
`.env` と `.streamlit/secrets.toml` は誤って秘密情報をコミットしないようGit管理対象外にしています。
Pillowはアップロード画像の検証・向きの補正・PNG化に使用します。画像生成APIや漫画ページの自動合成は実装していません。
第3段階でも追加の依存パッケージは不要で、既存のIntel Mac向け構成を維持しています。

## テスト

仮想環境を有効にした状態で実行します。

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

テストは一時フォルダを使うため、実際の保存データを書き換えません。
JSONの日本語保存・読み込み、更新、同名プロジェクト、入力エラー、不正なJSON、保存失敗時の保護を確認します。
StreamlitのAppTestでは、入力→保存→編集→新しいセッションでの再読み込みまで確認します。
第2段階では、JSONの表記揺れと入力エラー、UTF-8ファイルの読み込み、プロンプトの内容、履歴の復元・破損・同時保存を検証します。
外部通信を禁止したAppTestで、貼り付け→ページ編集→復元→再起動後の再読み込みも確認します。
第3段階ではキャラクターの登録・編集・削除、参照画像の基準選択、画像の形式・サイズ・透過・向き、
コマ別指示とプロンプト、候補の採用変更と保持、保存失敗・競合・破損設定の保護を確認します。
AppTestの画像アップロードはファイル選択の入力部分だけを模擬し、その後の検証・PNG化・保存・再読み込みは実際の処理を通します。
テストにもAPIキーや外部APIへの接続は必要ありません。

クラウドではLinux・Python 3.11 / 3.12で、それぞれ128件のテストが成功しています。
依存関係の整合性と、Python 3.11でのStreamlitサーバーの起動・HTTP応答も確認しています。
Python 3.11・macOS 10.15・Intel向けの依存パッケージ一式を
ソースビルドなしで取得できることを確認しています（Macでの実行確認ではありません）。

## 実装と変更範囲

- 既存split_dialogue・人物UUIDを再利用したセリフ／ナレーション抽出。曖昧な話者は手動確認。元本文と読みを分離。
- 人物／ナレーター別の声・速度と、発話別の通常・怒り・悲しみ・ささやき設定。モックを既定にする。
- 公式資料で比較したPolly Standard / Neuralのアダプター。SigV4・固定HTTPS・自動再試行なし・応答利用量・エラー秘匿化。
- 全有料送信をBudgetedExecutor経由に限定。脚本確定・確認済み料金・機能フラグ・対象別承認・共有予算を照合。
- 内容ハッシュの音声キャッシュ、変更発話のみ再生成、候補履歴、試聴確認、原子的保存・ロック・版競合検知。
- タイムアウト／利用量不明の予約保持、課金済み保存失敗から同じジョブで追加送信なしに復旧。請求照合済みジョブの明示終了。
- WAV実フレームと任意のffprobeから尺を計測し、独立JSONとSRTを履歴保存。
- 6工程を維持した任意の音声制作画面。選択中の画面・音声だけ読み込む。

追加コードは `manga/voice_*.py` に分割し、1ファイル最大169行。
既存製品コードの変更はnavigationへの遅延ルートと、予算台帳への読取専用request_statusだけです。
requirementsを変更せず、音声SDK・MLモデルの追加インストールは不要です。
仕様・費用・テスト・操作・公式比較はdocs、料金とタイムライン例はexamples、無料検証スクリプトはscriptsへ追加しました。
CIは既存Python 3.11／3.12の全pytestを再利用し、新ブランチのpushも実行対象にしました。

## 8ページ24コマの実ファイル検証

```bash
python scripts/verify_voice.py --output /workspace/artifacts/voice-phase3-demo-20261024
```

実ユーザーデータを使わず、3人物＋ナレーター、初めの3コマに5発話・残りは無音の専用作品を作成しました。
5発話を生成→同じ5発話をキャッシュ再利用→1セリフ変更後はその1件のみ生成し、旧音声も含む6WAVを保持しました。
24シーンのJSONと5字幕のSRTを保存し、全体尺38,710msと音声の実フレームを照合しました。ffprobeも実行しました。
これは実音声ではなく**確認用トーン**のfixtureで、本編3〜5分の完成動画を検証したものではありません。
同じ出力フォルダへ再実行すると拒否され、全31ファイルのSHA-256が変わらないことも確認しました。
配布用JSON例は独立バリデーターで検証済みです。対応WAVはソースブランチに入れていません。

## 保護したもの・残るリスク

story/schema_version:1、人物ID、参照画像、採用画像、作画指示、review、composition、既存出力・GitHub作品同期は形式を変えていません。
`works/` と `data/projects/` に追跡対象の変更はなく、新しい音声バイナリをGitへ追加しません。
新ファイルだけのvoice.jsonとvoice/へ保存し、共有予算ゲートは上限や請求不明時の停止条件を緩和していません。

- Intel Mac/macOS 12実機、実AWS認証、実際の日本語音声品質、AWS最終請求は未検証。別途承認された少量試験が必要。
- 感情はSSMLの演技プリセットで、Neuralささやきは小声の近似。音声の自然さは人間が確認する。
- 標準ライブラリのAWS署名アダプターはモックとHTTP解析を検証済みだが、実プロバイダー結合は未実行。
- 為替・税は利用者設定の上限仮定。共有台帳と初期化記録を全ワーカーで維持・バックアップする。
- 応答保存前のディスク故障では音声を復元できない場合がある。請求履歴を消さず、手動照合と新規生成判断を必要とする。
- 保存先はファイルロック・ハードリンク対応が必要。音声は既存GitHub同期に自動追加せず、作品フォルダ全体を別途バックアップする。
- 音声・画像・台本が変わったタイムラインは再出力する。公開前レビュー・SNSの開示条件・素材権利の確認は自動化しない。
